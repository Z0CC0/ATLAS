# Accessibility — WCAG 2.2 level AA

## Always — every component, asked or not

**The right element.** A button is a `button`, a link is an `a` with `href`, a field is an
`input` with a `label`. A `div` with a click handler is none of these: it has no role, no
keyboard, no name. ARIA is for what HTML cannot say, and a wrong ARIA attribute is worse
than none.
**A name.** Every control has one a screen reader will speak: visible text, a `label`
tied to the field, or `aria-label` on an icon-only button. The spoken name contains the
visible label (2.5.3).
**Keyboard.** Everything that works with a pointer works with keys, in an order that
follows the screen (2.1.1). Focus is always visible (2.4.7) and not hidden under a sticky
bar (2.4.11). Nothing traps it (2.1.2). No positive `tabindex`.
**Images.** `alt` says what the image is for; decoration gets `alt=""` (1.1.1).
**Contrast.** Text 4.5:1; large text (24 px, or 18.66 px bold) 3:1 (1.4.3). Control
boundaries, icons that carry meaning and focus rings 3:1 against what is next to them
(1.4.11). Measured, not judged by eye.
**Not colour alone.** An error, a state, a series in a chart has a second signal: text, an
icon, a pattern (1.4.1).
**Size.** Pointer targets at least 24 by 24 CSS pixels, or spaced to that (2.5.8). Platform
guidance is larger and is followed on touch: 44 pt on iOS, 48 dp on Android.
**Motion.** `prefers-reduced-motion` is honoured; nothing flashes more than three times a
second (2.3.1); anything that moves by itself for more than five seconds can be paused
(2.2.2).

## Patterns that are usually wrong

**Forms.** A placeholder is not a label. Required is said in text and in `required` or
`aria-required`. An error is text next to its field, tied with `aria-describedby`, the
field marked `aria-invalid`; on submit, focus goes to the first invalid field or to a
summary (3.3.1, 3.3.3). `autocomplete` on personal fields (1.3.5). Nothing asked twice in
one flow (3.3.7); no puzzle to log in, and paste allowed in password fields (3.3.8).
**Dialogs.** The `dialog` element with `showModal()`, or `role="dialog"` with
`aria-modal`, a name, focus moved inside on open, kept inside while open, returned to the
opener on close, Escape closes.
**Menus, tabs, comboboxes, accordions.** The roles, states and keys of the ARIA Authoring
Practices pattern, whole or not at all: `aria-expanded` on the trigger, arrow keys where
the pattern says arrows. Prefer the project's component library when it has an accessible
one.
**Things that change.** A result that appears without a page load is announced:
`role="status"` or `aria-live="polite"` for results and saves, `role="alert"` for errors
needing attention now (4.1.3). The live region exists before its content changes.
**Structure.** One `h1`, headings in order without skipping; landmarks (`header`, `nav`,
`main`, `footer`); a skip link (2.4.1); a page title that names the page (2.4.2); `lang` on
the document (3.1.1). Tables of data have `th` with `scope`.
**Reflow and zoom.** Usable at 320 CSS pixels wide without scrolling in two directions
(1.4.10) and at 200% text (1.4.4). Zoom is never disabled.
**Dragging.** Anything done by dragging can also be done by single clicks or keys (2.5.7).
**Hover content.** Tooltips and popovers stay while pointed at, can be dismissed without
moving, and appear on focus too (1.4.13).

## Native

The same four needs under other names. iOS: `accessibilityLabel`, traits, and hint;
Dynamic Type respected; `accessibilityElements` order. Android: `contentDescription`,
roles through semantics, `sp` for text, touch targets 48 dp. React Native:
`accessibilityRole`, `accessibilityLabel`, `accessibilityState`.

## Audit

Automated first when the page can be opened: axe (`npx @axe-core/cli <url>`) or the
browser's audit, output to a file. It finds roughly a third of problems. Then by hand:
keyboard through every flow, zoom, the names of controls from the accessibility tree,
contrast of the real colours.

One line per problem, the format of `atlas-review` with the criterion added:

```
src/components/Modal.tsx:31  breaks  2.1.2  Tab leaves the open dialog and reaches the page behind. Use dialog.showModal() or keep focus inside.
src/pages/login.tsx:58  breaks  3.3.1  the error is a red border only. Add the message as text, tied with aria-describedby.
src/components/Tag.tsx:12  fragile  1.4.3  #8a8f98 on #ffffff is 3.2:1. Use the text-secondary token (4.6:1).
```

`breaks`: someone cannot complete the task. `fragile`: they can, with difficulty.
`unclear`: needs a real screen reader or a user to settle. Last line: counts per tier and
what was not tested. No audit ends with "accessible": it ends with what was checked.
