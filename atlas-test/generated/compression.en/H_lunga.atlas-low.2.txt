Cache keeps already-processed prefix of request, so later requests starting same way skip paying for it again. Works only on prefix — one different character at start, no reuse past that point. So stable parts go first, changing parts after, not reverse.

Writing to cache costs more than normal read, so first request more expensive. Gain starts from second request onward, grows with number of turns.

Pays off on long conversations with large stable context — system instructions, attached documentation, tool definitions. Doesn't pay off on single requests differing from each other, where you pay write and never read back.

Watch for system line changing every turn, like clock — kills reuse of everything after it.
