HTTPS is HTTP inside a channel encrypted by TLS.

Handshake:

1. Client opens the connection and lists the TLS versions and ciphers it supports.

2. Server picks a version and a cipher, then sends its certificate.

3. Client checks the certificate's signature by walking the chain up to a root it already holds.

4. Client and server agree on a session key, today typically with an elliptic curve Diffie-Hellman exchange.

The certificate binds a domain name to a public key and is signed by a certificate authority. It says **nothing about who runs the site**. It only shows that the domain controls that key.

The session key is symmetric because asymmetric encryption costs too much for real traffic.

After the handshake, traffic is encrypted and authenticated, so nobody in the middle can read or change it.

TLS 1.3 does the handshake in one round trip. TLS 1.2 needs two.
