Cache stores already-processed prefix of request, so later requests starting same way don't pay for that part again.

Reuse works **only on prefix**. One different character near start, and nothing from that point on gets reused. So stable parts go first and changing parts after, not other way round. Watch for system line that changes every turn, such as clock: it kills reuse of everything after it.

Cost: writing to cache costs more than normal read, so first request costs more. Gain starts from second request and grows with number of turns.

Pays off on long conversations with large stable context: system instructions, attached documentation, tool definitions.

Doesn't pay off on single requests that differ from each other. There you pay for write and never read it back.
