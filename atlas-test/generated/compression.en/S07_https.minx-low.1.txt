HTTPS is HTTP running inside a channel encrypted by TLS. Before any HTTP data is sent, client and server set up that channel with a handshake:

1. The client opens the connection and says which TLS versions and ciphers it supports.

2. The server picks a cipher and a version, and sends its certificate.

3. The client checks the certificate. The certificate binds a domain name to a public key and is signed by a certificate authority. The client verifies that signature by following the chain up to a root certificate it already holds.

4. Client and server agree on a session key. Today this is usually done with an elliptic curve Diffie-Hellman exchange.

The session key is symmetric because asymmetric encryption costs too much for real traffic. From then on, all traffic is encrypted and authenticated, so nobody in the middle can read it or change it.

TLS 1.3 does the handshake in a single round trip. TLS 1.2 needs two.

The certificate says nothing about who runs the site. It only proves that whoever controls that domain also controls that key.
