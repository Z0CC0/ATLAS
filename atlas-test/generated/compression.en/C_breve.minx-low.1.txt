Usually no. On column with only three values, B-tree index normally goes unused.

Planner prefers sequential scan whenever filter selects more than roughly 5-10 per cent of rows. With three values, each one typically matches far more than that.

Index still costs you on every write, plus disk space, so you pay without getting faster reads.

Exception: if one value is rare, partial index on just that value does work, e.g. `CREATE INDEX ON orders (id) WHERE status = 'failed';`. Queries filtering on that rare value will use it.
