HTTPS is HTTP inside a channel encrypted by TLS.

The handshake:

1. Client opens the connection and lists the TLS versions and ciphers it supports.

2. Server picks a cipher and a version, and sends its certificate.

3. Client checks the certificate's signature by walking the chain up to a root it already holds.

4. Client and server agree a session key, today typically with an elliptic curve Diffie-Hellman exchange.

The certificate binds a domain name to a public key. It is signed by a certificate authority.

The session key is symmetric because asymmetric encryption costs too much for real traffic.

After that, traffic is encrypted and authenticated. Nobody in the middle can read it or change it.

TLS 1.3 needs a single round trip for the handshake. TLS 1.2 needs two.

The certificate says **nothing about who runs the site**. It says only that the domain controls that key.
