Connection pool exhaustion, not a slow query.

`db/session.py:47` releases the connection only on success. On a handler exception, `release()` never runs — connection held until timeout. A few hundred failed requests, pool empties, every later request waits. That's the rising latency instead of hard errors.

Fix — wrap acquisition in try/finally:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Raising `pool_size` isn't a fix — delays the empty-pool moment, leak stays. Raise it only after this fix, and only if real load needs it.

Reproduce before/after:
```
pytest tests/test_pool.py -k exhaustion -x
```
