Cause: connection pool exhaustion, not slow query.

In middleware at `db/session.py:47`, connection released only on success path. When handler raises exception, `release()` never reached — connection stays held until timeout. After few hundred failed requests, pool empties, every later request waits. That's why rising latency instead of immediate errors.

Fix: wrap acquisition in try/finally, so release happens on error path too.

```
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Raising `pool_size` looks like fix but only masks it — pushes back moment pool empties, doesn't remove leak. Raise `pool_size` only after fix in, only if real load calls for it.

Reproduce before/after:

```
pytest tests/test_pool.py -k exhaustion -x
```
