HTTPS works by running ordinary HTTP inside a channel that TLS encrypts. Before any page data moves, client and server run a handshake:

1. Client opens connection and lists TLS versions and ciphers it supports.

2. Server picks one cipher and one version, and sends its certificate.

3. Client checks certificate. Certificate binds domain name to public key and carries signature from certificate authority. Client verifies that signature by walking chain up to root it already holds.

4. Client and server agree on session key, today usually through elliptic curve Diffie-Hellman exchange.

Session key symmetric because asymmetric encryption costs too much for real traffic.

From then on, traffic encrypted and authenticated. Nobody in the middle can read or modify it.

TLS 1.3 cuts handshake to one round trip. TLS 1.2 needs two.

One limit: certificate says **nothing about who runs site**. It says only that domain controls that key.
