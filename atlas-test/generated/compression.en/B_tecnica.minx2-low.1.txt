Connection pool exhaustion, not slow query. Middleware in `db/session.py:47` releases connection only on success path.

When handler raises, `release()` never reached, so connection stays held until timeout. After a few hundred failed requests pool empties and every later request waits for free connection. That's why you see rising latency instead of immediate errors.

Fix: wrap acquisition in try/finally so release also happens on error path:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Raising `pool_size` looks like fix but only masks leak. It delays the moment pool empties, and connections still leak. Raise it only after fix is in, and only if real load calls for it.

Reproduce before and after change:

```
pytest tests/test_pool.py -k exhaustion -x
```
