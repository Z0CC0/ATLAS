HTTPS is just HTTP run inside a channel encrypted by TLS.

Connection starts with client telling server which TLS versions and cipher suites it supports. Server picks version and cipher, sends back its certificate. Certificate binds domain name to public key, signed by a certificate authority — note it says nothing about who runs site, only that domain controls that key. Client checks signature by walking chain up to root it already trusts.

Then client and server agree on session key, usually via elliptic curve Diffie-Hellman exchange. Session key is symmetric — asymmetric crypto too costly for real traffic volume. After that, all traffic encrypted and authenticated: nobody in middle can read or modify it.

TLS 1.3 does this handshake in one round trip; TLS 1.2 needed two.
