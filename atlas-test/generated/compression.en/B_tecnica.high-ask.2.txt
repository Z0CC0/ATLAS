Connection pool exhaustion, not a slow query.

In db/session.py:47, the connection releases only on the success path. When a handler raises, release() never runs — that connection stays held until timeout. A few hundred failed requests later, the pool is empty and every new request queues, waiting for a free connection. That's the rising latency instead of hard errors.

Fix: wrap acquisition in try/finally.

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Raising pool_size is not a fix — it delays when the pool empties, leak stays. Raise pool_size only after this fix, and only if real load actually needs it.

Reproduce before/after:
```
pytest tests/test_pool.py -k exhaustion -x
```
