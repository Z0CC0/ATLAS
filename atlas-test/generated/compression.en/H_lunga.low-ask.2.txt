Prompt caching keeps already-processed prefix of a request, so later requests starting same way skip paying for it again. Works only on prefix — one different character at start, zero reuse past that point. So stable content goes first, changing content after, never reverse.

First request costs more: writing to cache costs more than normal read. Gain starts second request onward, grows with turn count.

Pays off on long conversations with large stable context — system instructions, attached docs, tool definitions. Doesn't pay off on single unrelated requests, where you pay write cost and never read it back.

Watch for: a system line changing every turn (clock, timestamp) kills reuse of everything placed after it — put anything that changes turn-to-turn last, not mixed into the stable block.
