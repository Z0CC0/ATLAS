Your pool is running out of connections. A slow query is not the cause.

The middleware at `db/session.py:47` releases the connection only when the handler succeeds. When the handler raises an exception, `release()` is never reached, so the connection stays held until it times out. After a few hundred failed requests the pool is empty and every later request waits for a connection. That's why latency keeps rising instead of requests failing straight away.

To fix it, wrap the acquisition in try/finally so the connection is also released when the handler fails:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Raising `pool_size` only hides the problem. The pool takes longer to empty, but connections still leak. Raise it only after the fix is in, and only if your real load needs it.

```
pytest tests/test_pool.py -k exhaustion -x
```
