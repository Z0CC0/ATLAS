HTTPS = HTTP inside channel encrypted by TLS.

Handshake: client opens connection, states which TLS versions and ciphers it supports. Server answers, picks cipher and version, sends certificate. Certificate binds domain name to public key, signed by certificate authority. Client verifies signature by walking chain up to root it already holds.

Then client and server agree session key — today typically via elliptic curve Diffie-Hellman exchange. Key symmetric, since asymmetric encryption costs too much for real traffic.

From there, traffic encrypted and authenticated — neither readable nor modifiable by anyone in middle.

TLS 1.3 cuts handshake to single round trip, against two in TLS 1.2.

Note: certificate says nothing about who runs site — only that domain controls that key.
