Ten million rows, no downtime allowed, so skip direct `ALTER COLUMN TYPE` — it rewrites whole table under ACCESS EXCLUSIVE lock, service down entire duration.

Steps:

1. Check every value convertible first: count rows not all digits (something like `SELECT count(*) FROM t WHERE colonna !~ '^\d+$'`).
2. Add new column: `ALTER TABLE t ADD COLUMN colonna_int integer`.
3. Backfill in batches of 10,000 rows, so no long lock held on table.
4. Add trigger keeping both columns in sync during migration (so writes hitting old column also update new one, and vice versa).
5. Change code to read from new column, ship it.
6. Only then drop old column: `ALTER TABLE t DROP COLUMN colonna`.

**Warning:** step 6 irreversible. Once dropped, data not coming back without restore from backup. Verify code fully migrated and stable before doing it.
