Root cause: connection pool exhaustion, not a slow query.

Middleware at `db/session.py:47` releases connection only on success path. When handler raises exception, `release()` never reached — connection stays held until timeout. After few hundred failed requests, pool empties, every later request waits on it. That's why you see rising latency instead of immediate errors — requests aren't failing fast, they're queuing for connections that never come back.

Fix: wrap acquisition in try/finally so release happens on error path too.

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Raising `pool_size` looks like fix but only masks it — pushes back moment pool empties, doesn't remove leak. Raise `pool_size` only after this fix in, and only if real load actually calls for it.

To reproduce before and after change:
```
pytest tests/test_pool.py -k exhaustion -x
```
