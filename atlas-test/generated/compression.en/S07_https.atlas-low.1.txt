HTTPS: HTTP inside channel encrypted by TLS.

Handshake starts: client opens connection, states which TLS versions and ciphers it supports. Server answers, picks cipher and version, sends its certificate — binds domain name to public key, signed by certificate authority. Client verifies signature by walking chain up to root already held.

Client and server then agree on session key, today typically via elliptic curve Diffie-Hellman exchange. Session key symmetric, since asymmetric encryption costs too much for real traffic. From there, traffic encrypted and authenticated — unreadable and unmodifiable by anyone in middle.

TLS 1.3 cuts handshake to single round trip, against two in TLS 1.2.

One caveat: certificate says nothing about who runs site — only that domain controls that key.
