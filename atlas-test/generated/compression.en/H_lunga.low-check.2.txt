Cache keeps already-processed prefix of request, so later requests starting same way don't pay for it again — works only on prefix: one different character at start, no reuse from that point on. So stable parts go first, changing parts after, not reverse. Writing to cache costs more than normal read, so first request more expensive; gain starts second request onward, grows with number of turns. Pays off on long conversations with large stable context: system instructions, attached docs, tool definitions. Doesn't pay off on single requests differing from each other — pay write, never read back. System line changing every turn, like clock, kills reuse of everything after it.
