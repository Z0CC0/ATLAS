Cache keeps already-processed prefix of request; later requests starting same way skip paying for it again.

Works only on prefix: one different character at start, no reuse from there on. So stable parts go first, changing parts after — not reverse.

Writing to cache costs more than normal read, so first request costs more than without caching.

Gain starts from second request onward, grows with number of turns.

Pays off on long conversations with large stable context: system instructions, attached docs, tool definitions.

Doesn't pay off on single requests differing from each other — pay write cost, never read back.

Even one line changing every turn, like clock in system prompt, kills reuse of everything after it.
