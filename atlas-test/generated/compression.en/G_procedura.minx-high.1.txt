Don't run `ALTER TABLE ... ALTER COLUMN TYPE` directly. It rewrites the whole table while holding an ACCESS EXCLUSIVE lock, so the service is down for the entire rewrite. Instead, migrate in steps, in this order:

1. Check that every existing value can be converted. Count the rows whose value is not all digits. If the count isn't zero, fix those rows before going on.

2. Add a new column:
   ```sql
   ALTER TABLE t ADD COLUMN colonna_int integer;
   ```

3. Fill the new column in batches of 10,000 rows, so the table is never locked for long.

4. Add a trigger that keeps the two columns in sync for the rest of the migration.

5. Change the code to read from the new column, and ship it.

6. Only after that, drop the old column:
   ```sql
   ALTER TABLE t DROP COLUMN colonna;
   ```
   This step can't be undone. Once the column is dropped, the data only comes back through a restore from backup. Before you run it, make sure the previous steps are complete and the new code is working in production.
