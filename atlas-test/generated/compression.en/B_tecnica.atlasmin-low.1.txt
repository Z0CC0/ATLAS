Cause: connection pool exhaustion, not slow query.

Middleware at db/session.py:47 releases connection only on success path. Handler raises exception → release() never reached, connection stays held until timeout. After few hundred failed requests, pool empties, every later request waits — why you see rising latency instead of immediate errors.

Fix: wrap acquisition in try/finally so release happens on error path too.

```
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Raising pool_size looks like fix but only masks it — pushes back moment pool empties, doesn't remove leak. Raise pool_size only after this fix in, and only if real load calls for it.

To reproduce before/after: `pytest tests/test_pool.py -k exhaustion -x`
