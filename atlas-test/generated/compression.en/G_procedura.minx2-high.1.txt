Don't use a direct `ALTER TABLE ALTER COLUMN TYPE`. It rewrites the whole table while holding an ACCESS EXCLUSIVE lock, so the service is down for as long as the rewrite takes. Do the change in these steps instead, in this order:

1. Check that every existing value can be converted. Count the rows that are not all digits; the count should be zero before you go on:
   ```sql
   SELECT count(*) FROM t WHERE colonna !~ '^[0-9]+$';
   ```
2. Add the new column:
   ```sql
   ALTER TABLE t ADD COLUMN colonna_int integer;
   ```
3. Fill the new column in batches of 10,000 rows, so no long lock is held on the table.
4. Add a trigger that keeps the two columns in step while the migration runs.
5. Change the code to read from the new column, and ship it.
6. Only after all of the above, drop the old column:
   ```sql
   ALTER TABLE t DROP COLUMN colonna;
   ```

Step 6 can't be undone. Once the column is dropped, the data only comes back through a restore from backup.
