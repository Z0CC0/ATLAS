x86 went through three phases. Until the mid-nineties, each chip added features to the machine you programmed directly. Then x86 became a translation layer over a different machine underneath. Finally, once clock speed stopped scaling, progress moved to more cores, wider vectors and cleverer hidden machinery.

8086 (1978): 16 bit, grew out of the 8080 and was compatible with it at source level. Backward compatibility was the rule from day one.

80286 (1982): brought protected mode, but it had no way back to real mode without a reboot.

80386 (1985): 32 bit, paged virtual memory and virtual 8086 mode, so old real-mode programs could run inside the protected environment. This is the shape x86 kept for a long time.

486 (1989): first level cache and maths coprocessor moved onto the chip itself.

Pentium (1993): superscalar. Two integer pipelines could retire two instructions per cycle.

Pentium Pro (1995): the real turning point. Out of order execution, and x86 instructions translated into internal micro-operations. From then on x86 is an interface, no longer the real machine underneath.

Pentium 4 (2000): chased frequency with a very long pipeline and hit the power wall.

AMD64 (2003): AMD extended the architecture to 64 bit, and Intel adopted the same instruction set. First time the dominant extension did not come from Intel.

Core 2 (2006): direction shifted from frequency to core count.

Across these generations the vector extensions kept growing: MMX, then SSE, AVX and AVX-512.

Today the complexity sits in the layers below the instruction set: branch prediction, cache hierarchy, speculative execution. Spectre and Meltdown in 2018 showed that speculative execution carried a security cost nobody had priced.
