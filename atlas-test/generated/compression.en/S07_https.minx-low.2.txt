HTTPS is plain HTTP carried inside a channel encrypted by TLS. Before any HTTP flows, client and server run a handshake:

1. The client opens the connection and says which TLS versions and ciphers it supports.

2. The server picks a cipher and a version, and sends its certificate.

3. The client checks the certificate's signature by following the chain up to a root certificate it already holds.

4. Client and server agree on a session key. Today this is usually done with an elliptic curve Diffie-Hellman exchange.

Certificate binds domain name to public key, signed by certificate authority.

Session key symmetric: asymmetric encryption too costly for real traffic.

After handshake, traffic encrypted and authenticated. Anyone in the middle can't read it or change it.

TLS 1.3 finishes handshake in one round trip. TLS 1.2 needs two.

**Certificate says nothing about who runs site.** It only proves that domain controls that key.
