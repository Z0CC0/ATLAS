Don't run `ALTER TABLE ... ALTER COLUMN TYPE` directly. It rewrites the whole table while holding an ACCESS EXCLUSIVE lock, so the service is down for the entire rewrite. Migrate in six steps, in this order:

1. Check that every existing value can be converted. Count the rows whose value is not all digits. If the count isn't zero, fix those rows before you go on.

2. Add the new column:
   ```sql
   ALTER TABLE t ADD COLUMN colonna_int integer
   ```

3. Fill `colonna_int` in batches of ten thousand rows, so no long lock is held on the table.

4. Add a trigger that keeps the two columns in step while the migration runs.

5. Change the code to read from `colonna_int`, and ship it.

6. Only after that, drop the old column:
   ```sql
   ALTER TABLE t DROP COLUMN colonna
   ```
   **This step can't be undone.** Once the column is dropped, the data only comes back if you restore from a backup. Don't run it until the new column is filled, the trigger has kept both columns in step, and the code reading from `colonna_int` is live.
