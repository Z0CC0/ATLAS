HTTPS is HTTP inside channel encrypted by TLS. Before any HTTP flows, client and server run TLS handshake:

1. Client opens connection, states which TLS versions and ciphers it supports.

2. Server answers with chosen cipher and version, sends its certificate.

3. Client checks certificate. Certificate binds domain name to public key and carries signature from certificate authority. Client verifies that signature by walking chain up to root it already holds.

4. Client and server agree session key, today typically with elliptic curve Diffie-Hellman exchange.

From that point, traffic encrypted and authenticated, so anyone in the middle can neither read nor modify it.

Session key symmetric because asymmetric encryption costs too much for real traffic. Asymmetric part serves only handshake.

TLS 1.3 cuts handshake to single round trip, against two in TLS 1.2.

**Certificate says nothing about who runs site.** It says only that domain controls that key.
