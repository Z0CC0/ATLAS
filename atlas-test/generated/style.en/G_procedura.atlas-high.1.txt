Never with a direct `ALTER TABLE ... ALTER COLUMN ... TYPE`: it rewrites the whole table under an ACCESS EXCLUSIVE lock, so the service is down for the entire duration. Six steps, in this order:

1. Check every existing value converts. Count the rows that are not all digits; the count must be zero before you go on.

2. Add the new column: `ALTER TABLE t ADD COLUMN colonna_int integer`.

3. Fill it in batches of ten thousand rows, so no long lock is held on the table.

4. Add a trigger that keeps the two columns in step for the whole migration.

5. Change the code to read from the new column, and ship it.

6. Only then drop the old column: `ALTER TABLE t DROP COLUMN colonna`.

Step six is irreversible. Once the column is dropped the data does not come back without a restore from backup, so do it only after step five is live and verified.
