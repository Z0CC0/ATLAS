Cache keeps already-processed prefix of a request. Later request starting the same way does not pay for that part again.

Works only on prefix: one different character at the start, no reuse from that point on. So stable parts go first, changing parts after, not the other way round.

Writing to cache costs more than normal read, so first request more expensive. Gain starts from second request onward, grows with number of turns.

Pays off on long conversations with large stable context: system instructions, attached documentation, tool definitions. Does not pay off on single requests that differ from each other: you pay the write, never read it back.

One trap: a system line that changes every turn, such as a clock, kills reuse of everything after it.
