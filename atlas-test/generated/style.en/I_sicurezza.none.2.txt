No. Anything that reaches the browser is readable. Obfuscation falls apart the moment someone opens the developer tools or watches the network requests, because the key has to be sent in clear to the service anyway.

The key belongs on the server. Your frontend calls an endpoint on your own backend, and that backend makes the call to the service with the key. Put a rate limit on that endpoint, or it becomes a free way for anyone to use your key through you.

If the key has already been published, treat it as compromised and rotate it at once. Removing it from the code is not enough: it stays in the repository history, and anyone with a clone already has it.
