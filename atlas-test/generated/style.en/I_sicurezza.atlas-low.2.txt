No. Anything that reaches the browser is readable. Obfuscation falls apart the moment someone opens the developer tools or looks at the network requests.

The key belongs on the server. The frontend calls an endpoint on its own backend, and that backend calls the service with the key.

That backend endpoint needs a rate limit, or it becomes a free way to use your key.

If the key has already been published, treat it as compromised and rotate it at once. Removing it from the code is not enough. Taking it out of a commit still leaves it in the repository history, and anyone with a clone already has it.
