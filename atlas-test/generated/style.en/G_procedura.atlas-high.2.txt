Never with a direct `ALTER TABLE ALTER COLUMN TYPE`: it rewrites the whole table under an ACCESS EXCLUSIVE lock, so the service is down for the entire duration. Do it in six steps, in this order.

1. Check every existing value is convertible: count the rows that are not all digits. Fix or decide on those before anything else.

2. Add the new column:

```sql
ALTER TABLE t ADD COLUMN colonna_int integer;
```

3. Fill it in batches of ten thousand rows, so no long lock is held on the table.

4. Add a trigger keeping the two columns in step during the migration, so writes to the old column land in the new one too.

5. Change the code to read from the new column, and ship it.

6. Only then drop the old column:

```sql
ALTER TABLE t DROP COLUMN colonna;
```

Step six is irreversible. Once the column is dropped the data does not come back without a restore from backup, so do it only after the new code is live and verified.
