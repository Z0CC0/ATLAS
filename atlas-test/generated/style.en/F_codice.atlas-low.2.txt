```js
function debounce(fn, ms) {
  let t;
  return (...args) => {
    clearTimeout(t);
    t = setTimeout(() => fn(...args), ms);
  };
}
```

Four points hold it together.

`clearTimeout(t)` must run before every new `setTimeout`, or timers pile up and `fn` fires more than once.

`t` must live in the closure, outside the returned function. Declared inside, every call gets its own timer and nothing gets debounced.

`...args` forwards the arguments. Without the spread, `fn` receives nothing.

This version returns nothing. If the return value matters, you need a Promise.

Opposite behaviour, run at once then ignore calls for a period, is a throttle, a different function.
