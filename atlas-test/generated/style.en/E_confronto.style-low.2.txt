Postgres, moving to Redis only when volume genuinely demands it.

With SELECT FOR UPDATE SKIP LOCKED Postgres enough up to roughly a thousand jobs per minute. Job sits in same transaction as data, so can never start while matching write rolled back. Persistence free: process dies, queue still there.

Redis handles far more volume, latency under a millisecond. Costs one more service to run, monitor and upgrade, and persistence must be configured: without AOF enabled restart loses queued jobs.
