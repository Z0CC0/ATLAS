Cache keeps the already-processed prefix of a request; later requests starting the same way do not pay for it again.

Prefix only: one different character at the start, no reuse from that point on. So stable parts first, changing parts after, not the other way round.

Cache write costs more than a normal read: first request more expensive. Gain starts from the second request, grows with number of turns.

Pays off on long conversations with large stable context: system instructions, attached documentation, tool definitions.

Does not pay off on single requests that differ from each other: you pay the write, never read it back.

A system line changing every turn, such as a clock, kills reuse of everything after it.
