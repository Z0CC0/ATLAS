Connection pool exhaustion, not slow query.

Middleware at db/session.py:47 releases connection only on success path. Handler raises, release() never reached, connection held until timeout. After few hundred failed requests pool empties, every later request waits. Hence rising latency, not immediate errors.

Fix: wrap acquisition in try/finally so release runs on error path too:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Raising pool_size only masks it: pushes back moment pool empties, leak stays. Raise it only after fix in, only if real load calls for it.

Reproduce before and after:

```
pytest tests/test_pool.py -k exhaustion -x
```
