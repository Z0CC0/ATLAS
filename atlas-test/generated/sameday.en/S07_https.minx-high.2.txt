HTTPS is HTTP running inside a channel that TLS encrypts.

The handshake:

1. Client opens the connection and lists the TLS versions and ciphers it supports.

2. Server picks a cipher and a version, and sends its certificate.

3. The certificate binds a domain name to a public key and is signed by a certificate authority. The client checks that signature by following the chain up to a root it already holds.

4. Client and server agree on a session key. Today this is typically done with an elliptic curve Diffie-Hellman exchange.

The session key is symmetric because asymmetric encryption costs too much for real traffic.

After the handshake, traffic is encrypted and authenticated. Nobody in the middle can read it or change it.

TLS 1.3 needs only one round trip for the handshake. TLS 1.2 needs two.

The certificate says **nothing about who runs the site**. It only shows that the domain controls that key.
