No. Obfuscating it won't protect it. Anything that reaches the browser can be read. Obfuscation falls apart as soon as someone opens the developer tools or looks at the network requests, because the key shows up there in plain text.

Here's how to do it instead:

1. **Keep the key on the server.** Your frontend calls an endpoint on your own backend, and that backend calls the service with the key. The browser never sees the key.
2. **Put a rate limit on that endpoint.** Otherwise anyone can call it in a loop and use your key for free.

If the key has already been in the frontend or in a commit, treat it as compromised and rotate it now. Removing it from the code isn't enough. Taking it out in a new commit doesn't erase it either, because it's still in the repository history, and anyone who already cloned the repo has it. The only fix is to rotate the key so the leaked one stops working.
