HTTPS is HTTP running inside a channel that TLS encrypts.

Handshake:

1. Client opens connection, states which TLS versions and ciphers it supports.

2. Server picks cipher and version, sends its certificate.

3. Client verifies certificate signature by walking chain up to root it already holds.

4. Client and server agree session key, today typically via elliptic curve Diffie-Hellman exchange.

Certificate binds domain name to public key and is signed by certificate authority. It says nothing about who runs site, only that domain controls that key.

Session key is symmetric because asymmetric encryption costs too much for real traffic.

After handshake, traffic is encrypted and authenticated. Nobody in middle can read or modify it.

TLS 1.3 handshake takes one round trip. TLS 1.2 takes two.
