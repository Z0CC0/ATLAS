HTTPS is HTTP running inside a channel that TLS encrypts.

1. Client opens connection and lists the TLS versions and ciphers it supports.

2. Server picks a cipher and version, then sends its certificate.

3. Certificate binds a domain name to a public key and is signed by a certificate authority. Client checks the signature by walking the chain up to a root it already holds.

4. Client and server agree a session key, today usually with an elliptic curve Diffie-Hellman exchange. The key is symmetric because asymmetric encryption costs too much for real traffic.

5. From then on, traffic is encrypted and authenticated. Nobody in the middle can read or change it.

TLS 1.3 needs one round trip for the handshake. TLS 1.2 needs two.

Certificate says nothing about who runs the site. It says only that the domain controls that key.
