Connection pool exhaustion, not slow query.

`db/session.py:47` middleware releases connection only on success path. Handler raises exception, `release()` never reached, connection held until timeout. Few hundred failed requests, pool empty, every later request waits. Hence rising latency, not immediate errors.

Fix: wrap acquisition in try/finally, release runs on error path too:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Raising `pool_size` only masks it: pool empties later, leak stays. Raise `pool_size` only after fix, only if real load calls for it.

Reproduce before and after change:

```
pytest tests/test_pool.py -k exhaustion -x
```
