HTTPS is HTTP running inside a channel that TLS encrypts. Before any HTTP data moves, client and server run a TLS handshake:

1. **Client hello.** The client opens the connection. It lists the TLS versions and ciphers it supports.
2. **Server hello.** The server picks one version and one cipher. It also sends its certificate.
3. **Certificate check.** A certificate binds a domain name to a public key. A certificate authority signs it. The client checks the signature by walking the chain up to a root certificate it already holds.
4. **Key agreement.** Client and server agree on a session key. Today this is usually an elliptic curve Diffie-Hellman exchange.
5. **Encrypted traffic.** After the handshake, all traffic is encrypted and authenticated. Anyone in the middle can't read it or change it.

**Why a symmetric session key?** Asymmetric encryption costs too much to use on real traffic. It only helps set up the connection. The session key then encrypts the data.

**TLS 1.3 vs 1.2.** TLS 1.3 needs only one round trip for the handshake. TLS 1.2 needs two, so TLS 1.3 connections start faster.

**Limit.** A certificate says nothing about who runs the site. It only proves that whoever controls the domain holds that key. A padlock means the connection is private, not that the site can be trusted.
