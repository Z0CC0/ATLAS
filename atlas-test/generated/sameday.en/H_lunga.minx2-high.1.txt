Cache keeps already-processed prefix of request. Later requests starting same way don't pay for it again.

Works on prefix only: one different character at start, no reuse from that point on. So stable parts first, changing parts after, never reverse.

Cache write costs more than normal read, so first request more expensive. Gain starts from second request onward, grows with number of turns.

Pays off: long conversations with large stable context, such as system instructions, attached documentation, tool definitions.

Doesn't pay off: single requests differing from each other. Write paid, never read back.

System line changing every turn, such as clock, kills reuse of everything after it.
