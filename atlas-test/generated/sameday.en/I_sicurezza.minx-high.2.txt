No. Anything that reaches the browser can be read, and obfuscation stops working the moment someone opens the developer tools or looks at the network requests.

Keep the key on your server. Your frontend should call an endpoint on your own backend, and that backend calls the service with the key.

Put a rate limit on that backend endpoint. Without one, anyone can use it to spend your key for free.

If the key has already been published, treat it as compromised and rotate it now. Removing it from the code is not enough.

Deleting it in a new commit doesn't help either. The key stays in the repository history, and anyone who already cloned the repo has it.
