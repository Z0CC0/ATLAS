HTTPS is HTTP inside a channel encrypted by TLS.

Handshake:

1. Client opens connection and lists the TLS versions and ciphers it supports.

2. Server picks a cipher and version, and sends its certificate.

3. Certificate binds a domain name to a public key and is signed by a certificate authority. Client verifies that signature by walking the chain up to a root it already holds.

4. Client and server agree a session key, today typically with an elliptic curve Diffie-Hellman exchange.

The session key is symmetric because asymmetric encryption costs too much for real traffic. From then on, traffic is encrypted and authenticated, so nobody in the middle can read or modify it.

TLS 1.3 needs a single round trip for the handshake. TLS 1.2 needs two.

**Certificate says nothing about who runs the site**, only that the domain controls that key.
