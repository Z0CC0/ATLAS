Don't use a direct `ALTER TABLE ... ALTER COLUMN TYPE`. It rewrites the whole table while holding an ACCESS EXCLUSIVE lock, so the service stays down for as long as the rewrite runs. Migrate through a new column instead, in this order:

1. Check that every existing value can be converted. Count the rows whose value is not all digits. If the count is above zero, deal with those rows before you go on.

2. Add the new column:
   ```sql
   ALTER TABLE t ADD COLUMN colonna_int integer;
   ```

3. Fill the new column in batches of 10,000 rows. Small batches mean no long lock is ever held on the table.

4. Add a trigger that keeps the two columns in step while the migration runs, so rows written during the backfill stay in sync.

5. Change the code to read from `colonna_int`, and ship it.

6. Only after all of that, drop the old column:
   ```sql
   ALTER TABLE t DROP COLUMN colonna;
   ```
   You can't undo this step. Once the column is dropped, the data comes back only by restoring from backup. Make sure step 5 is live and working before you run it.
