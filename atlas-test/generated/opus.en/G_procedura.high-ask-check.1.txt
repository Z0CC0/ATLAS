internal knowledge

Don't run `ALTER TABLE ... ALTER COLUMN TYPE` directly. It rewrites the whole table while holding an ACCESS EXCLUSIVE lock, so the service is down for as long as the rewrite takes. Do it in six steps instead, in this order:

1. Check that every existing value can be converted. Count the rows where the value is not all digits. That count needs to be zero before you go on.

2. Add the new column:
   ```sql
   ALTER TABLE t ADD COLUMN colonna_int integer
   ```

3. Fill it in batches of 10,000 rows, so no long lock is held on the table.

4. Add a trigger that keeps the two columns in step during the migration.

5. Change the code to read from `colonna_int`, and ship it.

6. Only after that, drop the old column:
   ```sql
   ALTER TABLE t DROP COLUMN colonna
   ```

**Step 6 can't be undone.** Once the column is dropped, the only way to get the data back is to restore from backup. Don't run it until the code reading `colonna_int` is live in production.
