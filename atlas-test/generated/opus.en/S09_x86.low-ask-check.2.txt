internal knowledge

Story starts slightly before eighties: 8086 of 1978, 16-bit chip grown out of 8080 and compatible with it at source level. Every later step keeps that compatibility, so each generation adds new capability on top of what came before.

80286 (1982) introduces protected mode, but with an awkward limit: once in protected mode, no way back to real mode without a reboot.

80386 (1985) is the step that defines the architecture for decades: 32 bit, paged virtual memory, and virtual 8086 mode, which lets old 16-bit code run inside the new protected environment. 486 (1989) then pulls first-level cache and maths coprocessor onto the chip itself.

Pentium (1993) goes superscalar: two integer pipelines, able to retire two instructions per cycle. Pentium Pro (1995) brings the deeper change: out-of-order execution, with x86 instructions translated into internal micro-operations. **From that point x86 is an interface, no longer the real machine underneath.** Instruction set stays; what executes it becomes something else.

Pentium 4 (2000) chases frequency with very long pipeline and hits the power wall. Clock speed stops being the road forward.

Next major extension comes from outside Intel: in 2003 AMD extends architecture to 64 bit with AMD64, and Intel adopts the same instruction set. First time dominant extension does not come from Intel.

From 2006, with Core 2, direction shifts from frequency to core count. Across all these generations vector extensions keep growing: MMX, then SSE, then AVX, then AVX-512.

Today complexity sits in layers below instruction set: branch prediction, cache hierarchy, speculative execution. **Spectre and Meltdown in 2018 show that speculative execution carried a security cost nobody had priced.** Machinery that made x86 fast for twenty years turns out to leak information.
