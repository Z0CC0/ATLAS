Prompt caching saves the already-processed start of a request, so later requests that begin the same way don't pay for that part again.

It only works on the prefix. If one character differs near the start, nothing after that point gets reused. So put stable content first and changing content after it, never the other way round.

Writing to the cache costs more than a normal read, so the first request costs more. Savings start from the second request and grow with each turn.

**It pays off** in long conversations with a large stable context: system instructions, attached documentation, tool definitions. Those get written once and then read back cheaply on every turn.

**It doesn't pay off** for single requests that differ from each other. You pay for the write and never read it back.

Watch for a system line that changes every turn, such as a clock. It breaks reuse for everything after it, so move it to the end or remove it.
