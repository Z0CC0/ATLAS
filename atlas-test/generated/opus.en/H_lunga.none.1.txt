## How prompt caching works

When you send a request to a model, it first has to process all the input text before it can start answering. Prompt caching saves that already-processed beginning, the **prefix**, so a later request that starts the same way doesn't pay to process it again. It picks up from where the cached part ends.

The important word is *prefix*. Reuse only works from the start of the request and stops at the first difference. If one character changes near the top, nothing after that point is reused, even if the rest is identical.

### What this means for how you build prompts

Put the **stable parts first** and the **changing parts last**:

1. System instructions
2. Tool definitions
3. Attached documentation or reference material
4. The conversation so far
5. The new user message

If you reverse that order, for example by putting a per-request detail above the big stable block, the cache breaks at that detail every time.

A common mistake is a system line that changes on every turn, such as the current time ("It is now 14:32:07"). The cache breaks right there, so everything after that line has to be processed again on every request. If you need something like that, move it toward the end.

### The cost trade-off

Caching isn't free. **Writing** to the cache costs more than a normal read of the input, so the first request is more expensive than it would be without caching. The savings come from reading the cache back:

- **Request 1:** you pay the higher cost of writing to the cache.
- **Request 2 onward:** the cached prefix is reused and you start saving.
- **More turns:** each turn reads the same prefix again, so the savings keep adding up.

### When it pays off

**Worth it:** long conversations or repeated calls that share a large, unchanging context, such as long system instructions, attached documentation and many tool definitions. You pay the write once and get the benefit on every turn after it.

**Not worth it:** one-off requests that all differ from each other. Each one pays the extra cost to write to the cache, and nothing ever reads it back, so you end up paying more than without caching.

**Rule of thumb:** caching helps when the same large beginning comes up again and again. Keep that beginning byte-for-byte identical and put everything that changes after it.
