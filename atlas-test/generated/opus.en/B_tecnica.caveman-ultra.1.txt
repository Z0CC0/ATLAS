Your connection pool is running out. The cause is not a slow query.

**Cause:** the middleware at `db/session.py:47` releases the connection only when the request succeeds. When the handler raises an exception, `release()` never runs. That connection stays held until it times out. After a few hundred failed requests the pool is empty, and every request after that waits for a connection. That is why latency keeps rising instead of you getting errors right away.

**Fix:** wrap the acquisition in `try/finally` so the connection is also released when there is an error:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

**Don't raise `pool_size` as the fix.** A bigger pool only hides the problem. The pool still empties, just later, and connections still leak. Raise `pool_size` only after the fix is in, and only if your real load needs it.

**Check it:** run this before and after the change to reproduce the behaviour:

```
pytest tests/test_pool.py -k exhaustion -x
```
