Don't run `ALTER TABLE ... ALTER COLUMN TYPE` directly. It rewrites the whole table while holding an ACCESS EXCLUSIVE lock, so the service is down for the entire rewrite. Move the data to a new column instead, in this order:

1. Check that every existing value can be converted: count the rows that are not all digits. Fix those rows before you go on.

2. Add the new column:
   ```sql
   ALTER TABLE t ADD COLUMN colonna_int integer;
   ```

3. Fill it in batches of ten thousand rows, so no long lock is held on the table.

4. Add a trigger that keeps the two columns in step for the rest of the migration.

5. Change the code to read from `colonna_int`, and ship it.

6. Only after all of that, drop the old column:
   ```sql
   ALTER TABLE t DROP COLUMN colonna;
   ```
   You can't undo this step. Once the column is dropped, the data only comes back by restoring from a backup. Run it only after step 5 is shipped and working.
