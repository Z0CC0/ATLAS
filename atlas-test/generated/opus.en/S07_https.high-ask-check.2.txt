internal knowledge

HTTPS is HTTP running inside a TLS-encrypted channel.

**Handshake:**

1. Client opens connection, lists TLS versions and ciphers it supports.

2. Server picks cipher and version, sends certificate.

3. Certificate binds domain name to public key, signed by certificate authority. Client verifies signature by walking chain up to root it already holds.

4. Client and server agree session key, today typically via elliptic curve Diffie-Hellman exchange.

Session key symmetric: asymmetric encryption costs too much for real traffic.

From then on, traffic encrypted and authenticated. Nobody in the middle can read or modify it.

TLS 1.3 handshake: one round trip. TLS 1.2: two.

**Limit:** certificate says nothing about who runs site. Only that domain controls that key.
