Usually no.

On a column with only three distinct values, the planner normally won't use a plain B-tree index.

It picks a sequential scan instead when the filter matches more than roughly 5-10 per cent of the rows, and with three values each one usually matches far more than that.

The unused index still costs you on every write and takes up disk space.

The exception is when one of the values is rare. A partial index on just that value does get used:

```sql
CREATE INDEX ON orders (id) WHERE status = 'failed';
```
