Prompt caching stores the already-processed prefix of a request, so any later request that starts the same way doesn't pay to process that part again.

It works only on the prefix. If even one character differs near the start, nothing from that point onward gets reused. So put the stable parts first and the changing parts after, never the other way round.

Writing to the cache costs more than a normal read, so the first request costs more. The savings start with the second request and grow with each turn that reuses the prefix.

It pays off on long conversations with a large stable context: system instructions, attached documentation and tool definitions.

It doesn't pay off on single requests that each differ. You pay for the cache write and never read it back.

One common trap: a system line that changes every turn, such as a clock, breaks reuse for everything after it. Move a line like that to the end, or remove it.
