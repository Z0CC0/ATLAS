Don't run `ALTER TABLE ... ALTER COLUMN TYPE` directly. It rewrites the whole table while holding an `ACCESS EXCLUSIVE` lock, so the service is down for the whole rewrite. Do the change in steps, in this order:

1. **Check every value converts.** Count the rows where `colonna` is not all digits. Fix those rows first, until the count is zero.
2. **Add the new column:**
   ```sql
   ALTER TABLE t ADD COLUMN colonna_int integer;
   ```
3. **Backfill in batches of 10,000 rows.** Small batches mean no long lock is ever held on the table.
4. **Add a trigger that keeps `colonna` and `colonna_int` in step** for the rest of the migration. New writes then land in both columns.
5. **Change the code to read from `colonna_int`, and ship it.**
6. **Only after that, drop the old column:**
   ```sql
   ALTER TABLE t DROP COLUMN colonna;
   ```

**Warning:** step 6 can't be undone. Once `colonna` is dropped, the only way to get its data back is a restore from backup. Run it only after the code that reads `colonna_int` is live in production.
