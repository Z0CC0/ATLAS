Don't run `ALTER TABLE ... ALTER COLUMN ... TYPE integer` directly. It rewrites the whole table under an ACCESS EXCLUSIVE lock, so the service is down for the whole rewrite. Migrate through a new column in six steps, in this order:

1. Check that every existing value converts. Count the rows where `colonna` isn't all digits. If the count isn't zero, fix those rows before going further.

2. Add the new column:
   ```sql
   ALTER TABLE t ADD COLUMN colonna_int integer;
   ```

3. Fill `colonna_int` in batches of 10,000 rows so you never hold a long lock on the table.

4. Add a trigger that keeps `colonna` and `colonna_int` in step for the rest of the migration. Writes that arrive during and after the backfill then land in both columns.

5. Change the code to read from `colonna_int` and ship it.

6. Only after step 5 is shipped and working, drop the old column:
   ```sql
   ALTER TABLE t DROP COLUMN colonna;
   ```
   **This step can't be undone.** Once the column is dropped, its data only comes back by restoring from backup. Don't run it until you're sure nothing still reads `colonna`.
