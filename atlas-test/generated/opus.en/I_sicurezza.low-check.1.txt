No. Anything that reaches the browser can be read, and obfuscation stops working as soon as someone opens the developer tools or looks at the network requests.

Keep the key on your server. Your frontend should call an endpoint on your own backend, and that backend calls the service with the key.

Put a rate limit on that backend endpoint. Without one, anyone can use the endpoint to spend your key for free.

If the key has already been published, treat it as compromised and rotate it right away. Removing it from the code is not enough.

Removing it in a new commit doesn't fix this either. The key stays in the repository history, and anyone who already cloned the repo has it.
