Your pool is running out of connections. It's a connection leak, not a slow query.

The middleware at `db/session.py:47` releases the connection only when the request succeeds. When the handler raises an exception, `release()` never runs and the connection stays held until it times out. After a few hundred failed requests the pool is empty and every request after that waits for a connection. That's why latency keeps climbing instead of requests failing right away.

To fix it, wrap the acquisition in try/finally so the connection is released on the error path too:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Raising `pool_size` looks like a fix but only hides the problem. The pool empties later, and connections still leak. Raise it only after the fix is in, and only if your real load needs it.

Run this to reproduce the problem before and after the change:

```
pytest tests/test_pool.py -k exhaustion -x
```
