Connection pool exhaustion, not slow query. Middleware at `db/session.py:47` leaks connections whenever handler raises.

At that line, connection released only on success path. When handler throws, `release()` never reached, so connection stays held until timeout. After few hundred failed requests, pool empties and every later request waits for free connection. That's why you see latency rising instead of immediate errors.

Fix: wrap acquisition in `try/finally` so release also happens on error path.

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Don't raise `pool_size` as fix. It only masks the leak: pool still empties, just later. Put this fix in first. After that, raise `pool_size` only if real load calls for it.

To reproduce behaviour before and after change:

```
pytest tests/test_pool.py -k exhaustion -x
```
