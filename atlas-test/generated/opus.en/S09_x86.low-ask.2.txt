The story starts slightly before the eighties: 8086, 1978, 16 bit, grew out of 8080 and stayed compatible with it at source level. That pattern of carrying the past forward runs through everything after.

**Early eighties: modes and memory.** 80286 (1982) introduced protected mode, but with a catch: no way back to real mode without a reboot. 80386 (1985) fixed what 286 left awkward. It brought 32 bit, paged virtual memory and virtual 8086 mode, so old 16-bit code could run inside the new protected world.

**Pulling things onto the chip.** 486 (1989) moved first-level cache and maths coprocessor onto the processor itself. Pentium (1993) went superscalar: two integer pipelines, able to retire two instructions per cycle.

**Turning point.** Pentium Pro (1995) introduced out-of-order execution and began translating x86 instructions into internal micro-operations. From then on, x86 became an interface, no longer the real machine underneath. Programs still speak x86; hardware executes something else.

**Frequency race and its end.** Pentium 4 (2000) chased clock speed with a very long pipeline and hit the power wall. From 2006, with Core 2, the direction shifted from frequency to core count.

**64 bit from outside Intel.** In 2003 AMD extended the architecture to 64 bit with AMD64, and Intel adopted the same instruction set. First time the dominant extension did not come from Intel.

**Vectors.** Across generations, vector extensions kept growing: MMX, then SSE, AVX, AVX-512.

**Today.** Complexity sits in layers below the instruction set: branch prediction, cache hierarchy, speculative execution. Spectre and Meltdown (2018) showed that speculative execution carried a security cost nobody had priced. The same machinery that made x86 fast also opened a way to leak data.
