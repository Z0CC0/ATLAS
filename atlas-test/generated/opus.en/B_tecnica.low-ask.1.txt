Connection pool exhaustion, not a slow query: connections leak whenever a handler raises an exception.

In middleware at `db/session.py:47`, connection released only on success path. When handler raises, `release()` never reached, so connection stays held until timeout. After a few hundred failed requests pool empties and every later request waits for a free connection. That's why latency keeps rising instead of requests failing right away with errors.

Fix: wrap acquisition in try/finally so release also happens on error path:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Raising `pool_size` looks like a fix but only hides the leak. Pool still empties, just later. Raise it only after fix is in, and only if real load calls for it.

To reproduce behaviour before and after the change:

```
pytest tests/test_pool.py -k exhaustion -x
```
