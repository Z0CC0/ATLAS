internal knowledge

Cache keeps already-processed prefix of request. Later requests starting same way don't pay for it again.

Works only on prefix: one different character at start, no reuse from that point on. So stable parts first, changing parts after, never other way round.

Writing to cache costs more than normal read, so first request is more expensive. Gain starts from second request, grows with number of turns.

Pays off: long conversations with large stable context, such as system instructions, attached documentation, tool definitions.

Doesn't pay off: single requests that differ from each other. You pay for write, never read it back.

Watch for system line changing every turn, such as clock: kills reuse of everything after it. Put it after stable parts.
