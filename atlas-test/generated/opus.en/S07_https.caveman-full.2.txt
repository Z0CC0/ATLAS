HTTPS is HTTP running inside a channel that TLS encrypts. HTTP itself does not change. TLS wraps it.

**Handshake**

1. Client opens the connection. It lists the TLS versions and ciphers it supports.
2. Server picks one version and one cipher. It sends back its certificate.
3. Certificate binds a domain name to a public key. A certificate authority (CA) signs it.
4. Client checks the signature by walking the chain up to a root certificate it already holds. If the chain ends at a trusted root, the key really belongs to that domain.
5. Client and server agree on a session key. Today this is usually an elliptic curve Diffie-Hellman (ECDHE) exchange.

**Why a symmetric session key**

Asymmetric encryption costs too much for real traffic. So public-key crypto only sets up the connection. A fast symmetric key then carries the data.

**After handshake**

All traffic is encrypted and authenticated. Anyone in the middle cannot read it or change it.

**TLS 1.2 vs 1.3**

TLS 1.2 handshake needs two round trips. TLS 1.3 needs only one, so connections start faster.

**What the padlock does not mean**

Certificate says nothing about who runs the site. It says only that whoever controls the domain also controls that key. A phishing site can have a valid certificate for its own domain.
