Connection pool exhaustion, not a slow query.

Middleware at `db/session.py:47` releases connection only on success path. When handler raises exception, `release()` never reached, so connection stays held until timeout. After a few hundred failed requests pool empties and every later request waits for a free connection. That's why you see rising latency instead of immediate errors.

Fix: wrap acquisition in try/finally so release also happens on error path:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Don't raise `pool_size` as the fix. It only hides the leak and delays the moment the pool empties. Raise it only after this fix is in, and only if real load calls for it.

To reproduce before and after the change:

```
pytest tests/test_pool.py -k exhaustion -x
```
