Connection pool exhaustion, not a slow query.

`db/session.py:47` middleware releases the connection only on the success path. When the handler raises, `release()` is never reached; connection stays held until timeout. After a few hundred failed requests the pool empties and every later request waits. That's why latency climbs instead of failing with immediate errors.

Fix: wrap acquisition in try/finally so release also runs on the error path:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Raising `pool_size` looks like a fix but only masks the leak: the pool still empties, just later. Raise `pool_size` only after the fix is in, and only if real load calls for it.

To reproduce before and after the change:

```
pytest tests/test_pool.py -k exhaustion -x
```
