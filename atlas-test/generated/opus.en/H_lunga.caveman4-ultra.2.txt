Cache stores the already-processed prefix of a request. Later requests that start the same way skip paying for that part again.

**Prefix only.** Reuse stops at the first character that differs. Change one character near the start and nothing after it is reused.

**Order matters.** Put the stable parts first and the changing parts after, never the reverse. A system line that changes every turn, like a clock, breaks reuse for everything after it.

**Cost curve:**
- Writing to the cache costs more than a normal read, so the first request is more expensive.
- Savings start from the second request and grow with the number of turns.

**Pays off:** long conversations with a large stable context, such as system instructions, attached documentation and tool definitions.

**Doesn't pay off:** one-off requests that differ from each other. You pay for the cache write and never read it back.
