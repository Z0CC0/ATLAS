Your database connection pool is running out, and the cause is a connection leak. It isn't a slow query.

## What's happening

In the middleware at `db/session.py:47`, the connection is released only when the handler succeeds. If the handler raises an exception, the code never reaches `release()`, so that connection stays checked out until it times out.

Each failed request holds on to one connection. After a few hundred failures the pool is empty, and every request after that has to wait for a connection to free up. That's why latency keeps rising until the API locks up, instead of requests failing straight away with errors.

## The fix

Wrap the acquisition in `try/finally` so the connection is released on the error path as well:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

## Don't just raise `pool_size`

Raising `pool_size` will look like it fixes the problem, but it only hides it. A bigger pool takes longer to empty, and the leak is still there. Make the fix above first. After that, raise `pool_size` only if your real load needs it.

## Check it

Run this before and after the change to reproduce the problem and confirm the fix:

```
pytest tests/test_pool.py -k exhaustion -x
```
