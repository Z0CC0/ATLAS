x86 history splits into three eras: first the instruction set grows, then clock speed rises, then parallelism and speculation carry performance.

**Foundations (1978–1985)**
- **8086 (1978):** 16 bit. Grows out of 8080, compatible at source level. Old code needs recompile, not rewrite. Compatibility is the pattern from day one.
- **80286 (1982):** Introduces protected mode. Flaw: no way back to real mode without reboot. That makes the mode awkward in practice.
- **80386 (1985):** Big leap. Brings 32 bit, paged virtual memory and virtual 8086 mode. Virtual 8086 mode lets old real-mode code run inside protected environment, so the 286 dead end gets fixed. Modern operating systems build on this chip's model.

**Integration and parallelism inside one core (1989–1995)**
- **486 (1989):** Pulls first level cache and maths coprocessor onto the chip. Fewer trips off-chip, much faster.
- **Pentium (1993):** Superscalar. Two integer pipelines can retire two instructions per cycle.
- **Pentium Pro (1995):** Key turning point. Introduces out of order execution. Translates x86 instructions into internal micro-operations. From here x86 is an interface, no longer the real machine underneath. Chip keeps the old instruction set outside and runs a different engine inside.

**Frequency race and its end (2000–2006)**
- **Pentium 4 (2000):** Chases frequency with very long pipeline. Hits power wall. Higher clocks now cost too much power and heat.
- **AMD64 (2003):** AMD extends architecture to 64 bit. Intel adopts same instruction set. First time dominant extension does not come from Intel.
- **Core 2 (2006):** Direction shifts from frequency to core count. More cores replace higher clocks.

**Throughout: vector extensions**
Each generation widens vector units: MMX, then SSE, then AVX, then AVX-512. More data processed per instruction.

**Today**
Complexity sits in the layers below the instruction set: branch prediction, cache hierarchy, speculative execution. Performance comes from guessing ahead and keeping data close.

That guessing has a cost. Spectre and Meltdown (2018) show speculative execution carried a security cost nobody had priced.

**Big picture:** x86 kept backward compatibility for more than 40 years. It did this by turning the instruction set into a stable interface over machines that kept changing underneath. That same hidden machinery now drives both the speed and some of the risk.
