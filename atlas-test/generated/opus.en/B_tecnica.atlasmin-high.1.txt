Connection pool exhaustion, not a slow query.

Middleware at `db/session.py:47` releases the connection only on the success path. When the handler raises an exception, `release()` is never reached, so the connection stays held until timeout. After a few hundred failed requests the pool is empty and every later request waits. That's why you see latency rising instead of immediate errors.

The fix is to wrap the acquisition in try/finally so the connection is released on the error path too:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Don't raise `pool_size` as the fix. It only masks the problem: the pool empties later, but connections still leak. Raise it only after this fix is in, and only if your real load calls for it.

To reproduce the problem before the change and confirm the fix after it, run:

```
pytest tests/test_pool.py -k exhaustion -x
```
