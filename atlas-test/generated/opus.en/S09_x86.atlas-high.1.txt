Over about forty years x86 went from a 16 bit chip to an instruction set that sits on top of a very different machine underneath. The gains moved from clock speed to core count, and the complexity moved into the layers you don't see.

8086 (1978): 16 bit, grown out of the 8080 and compatible with it at source level. It starts just before the eighties.

80286 (1982): protected mode arrives, but there is no way back to real mode without a reboot.

80386 (1985): 32 bit, paged virtual memory and virtual 8086 mode.

486 (1989): the first level cache and the maths coprocessor move onto the chip.

Pentium (1993): superscalar, with two integer pipelines that can retire two instructions per cycle.

Pentium Pro (1995): out of order execution, with x86 instructions translated into internal micro-operations. **From here x86 is an interface, no longer the real machine underneath.**

Pentium 4 (2000): a very long pipeline built to chase frequency, which hits the power wall.

AMD64 (2003): AMD extends the architecture to 64 bit and Intel adopts the same instruction set. It is the first time the dominant extension does not come from Intel.

Core 2 (2006): the direction shifts from frequency to core count.

Across these generations the vector extensions keep growing: MMX, SSE, AVX, AVX-512.

Today the complexity sits in the layers below: branch prediction, cache hierarchy, speculative execution.

Spectre and Meltdown (2018): **speculative execution turned out to carry a security cost nobody had priced.**
