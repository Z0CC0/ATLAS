Prompt caching stores the part of a request that has already been processed, the prefix, so later requests that start the same way don't pay to process it again.

It only works on the prefix. If one character near the start differs, nothing from that point on gets reused. So put the stable parts first and the parts that change after them, never the other way round.

A common trap is a system line that changes every turn, such as a clock. It breaks reuse for everything that comes after it.

Writing to the cache costs more than a normal read, so your first request costs more. The savings start with the second request and grow with each turn.

Caching pays off in long conversations with a large stable context, such as system instructions, attached documentation and tool definitions. It doesn't pay off for one-off requests that all differ from each other, because you pay for the cache write and never read it back.
