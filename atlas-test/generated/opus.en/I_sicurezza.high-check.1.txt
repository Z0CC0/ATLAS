No. Anything that reaches the browser can be read, and obfuscation stops working as soon as someone opens the developer tools or looks at the network requests.

Keep the key on your server. The frontend calls an endpoint on your own backend, and that backend calls the service with the key.

Put a rate limit on that backend endpoint. Without one, anyone can use it to spend your key for free.

If the key has already been published, treat it as compromised and rotate it now. Removing it from the code does not fix this.

Taking it out in a new commit isn't enough either. The key is still in the repository history, and anyone who already cloned the repo has it.
