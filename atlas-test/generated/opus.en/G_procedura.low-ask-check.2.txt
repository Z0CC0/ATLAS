internal knowledge

Don't run a direct `ALTER TABLE ... ALTER COLUMN ... TYPE`. It rewrites the whole table while holding an ACCESS EXCLUSIVE lock, so the service stays down for the entire rewrite. Do it in six steps instead, in this order:

1. Check that every existing value converts. Count the rows whose value is not all digits. The count must be zero before you go on.

2. Add the new column:
```sql
ALTER TABLE t ADD COLUMN colonna_int integer;
```

3. Fill it in batches of ten thousand rows, so no long lock is held on the table.

4. Add a trigger that keeps the two columns in step while the migration runs.

5. Change the code to read from `colonna_int`, and ship it.

6. Only then, drop the old column:
```sql
ALTER TABLE t DROP COLUMN colonna;
```

Step 6 cannot be undone. Once the column is dropped, its data only comes back by restoring from backup. Run it only after the code reading `colonna_int` is live and working.
