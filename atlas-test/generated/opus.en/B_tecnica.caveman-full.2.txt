Cause is connection pool exhaustion, not a slow query.

**What happens:**
- The middleware at `db/session.py:47` releases the connection only on the success path.
- When a handler raises an exception, `release()` is never reached. That connection stays held until timeout.
- After a few hundred failed requests, the pool is empty. Every later request waits for a free connection.
- That is why latency rises and the API locks up instead of returning errors right away.

**Fix:** wrap the acquisition in `try/finally`, so the release also runs on the error path.

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

**Don't raise `pool_size` as the fix.** It looks like a fix but only hides the leak. The pool still empties, just later. Raise `pool_size` only after the fix is in, and only if real load calls for it.

**Check:** run this before and after the change to reproduce the behaviour:

```
pytest tests/test_pool.py -k exhaustion -x
```
