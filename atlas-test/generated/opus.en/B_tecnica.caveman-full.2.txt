Problem is connection pool exhaustion, not slow query.

**Cause:** Middleware at `db/session.py:47` releases connection only on success path. Handler raises exception, so `release()` never runs. Connection stays held until timeout. After few hundred failed requests, pool empties. Every later request then waits for free connection. That is why latency rises instead of immediate errors.

**Fix:** Wrap acquisition in `try/finally`. Release then runs on error path too:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

**Do not raise `pool_size` as fix.** Bigger pool only masks leak. Pool still empties, only later. Raise `pool_size` only after fix is in, and only if real load needs it.

**Verify:** Run before and after change to reproduce behaviour:

```
pytest tests/test_pool.py -k exhaustion -x
```
