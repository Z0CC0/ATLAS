Prompt caching stores the already-processed prefix of a request. Later requests that start the same way don't pay for that part again.

It works only on the prefix. If one character differs near the start, nothing is reused from that point on. Put the stable parts first and the changing parts after, never the other way round.

Writing to the cache costs more than a normal read, so the first request is more expensive. The savings start with the second request and grow with each turn.

It pays off on long conversations with a large stable context, such as system instructions, attached documentation and tool definitions.

It doesn't pay off on single requests that differ from each other. You pay for the write and never read it back.

Watch for a system line that changes every turn, such as a clock. It stops reuse of everything after it.
