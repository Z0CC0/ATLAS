HTTPS is HTTP running inside a channel encrypted by TLS. The connection works like this:

1. **Client hello.** The client opens the connection and lists the TLS versions and ciphers it supports.
2. **Server hello.** The server picks one version and one cipher, then sends its certificate.
3. **Certificate check.** The certificate links a domain name to a public key, and a certificate authority signs it. The client checks that signature by following the chain up to a root certificate it already has.
4. **Key agreement.** Client and server agree on a session key. Today this is usually done with an elliptic curve Diffie-Hellman exchange. The session key is symmetric because asymmetric encryption costs too much for real traffic.
5. **Encrypted traffic.** From here on, all traffic is encrypted and authenticated. Anyone in the middle can't read it and can't change it.

**Speed:** TLS 1.3 completes the handshake in a single round trip. TLS 1.2 needs two.

**Limit:** The certificate doesn't tell you who runs the site. It only shows that whoever controls the domain also controls that key.
