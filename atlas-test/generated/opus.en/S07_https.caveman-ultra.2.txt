HTTPS is HTTP running inside a channel encrypted by TLS. Before any HTTP data moves, TLS runs a handshake.

**Handshake:**
1. Client opens connection. It lists the TLS versions and ciphers it supports.
2. Server picks one version and one cipher, then sends its certificate.
3. Client checks the certificate. A certificate binds a domain name to a public key, and a certificate authority signs it. Client verifies the signature by walking the chain up to a root certificate it already holds.
4. Client and server agree on a session key. Today this is typically an elliptic curve Diffie-Hellman exchange.

**Why the session key is symmetric:** asymmetric encryption costs too much for real traffic. It works for the handshake but not for bulk data.

**After the handshake:** traffic is encrypted and authenticated. Anyone in the middle can't read it or change it.

**Speed:** TLS 1.3 finishes the handshake in one round trip. TLS 1.2 needs two.

**Limit:** the certificate says nothing about who runs the site. It only says that the domain controls that key. A padlock means your connection to that domain is secure. It does not mean the site is trustworthy.
