internal knowledge

Don't run `ALTER TABLE ... ALTER COLUMN TYPE` directly. It rewrites the whole table while holding an ACCESS EXCLUSIVE lock, so the service is down for as long as the rewrite takes. Migrate through a new column instead, and follow these steps in this order:

1. Check that every existing value can be converted. Count the rows whose value is not all digits. If the count isn't zero, fix those rows before you go on.

2. Add the new column:
   ```sql
   ALTER TABLE t ADD COLUMN colonna_int integer;
   ```

3. Fill the new column in batches of 10,000 rows, so no long lock is held on the table.

4. Add a trigger that keeps the two columns in step for the rest of the migration.

5. Change the code to read from `colonna_int`, and ship it.

6. Only after that, drop the old column:
   ```sql
   ALTER TABLE t DROP COLUMN colonna;
   ```

Step 6 can't be undone. Once the column is dropped, its data only comes back by restoring from a backup. Run it only after steps 1 to 5 are finished and the new code is live.
