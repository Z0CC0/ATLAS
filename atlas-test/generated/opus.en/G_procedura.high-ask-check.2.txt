internal knowledge

Don't run a direct `ALTER TABLE ... ALTER COLUMN ... TYPE`. It rewrites the whole table while holding an ACCESS EXCLUSIVE lock, so the service is down for the entire rewrite. Change the column in these steps instead, in this order:

1. Check that every existing value can be converted. Count the rows whose value is not all digits. Fix those rows before you go further.

2. Add the new column:
   ```sql
   ALTER TABLE t ADD COLUMN colonna_int integer;
   ```

3. Fill `colonna_int` in batches of ten thousand rows. This way no long lock is held on the table.

4. Add a trigger that keeps `colonna` and `colonna_int` in step while the migration runs.

5. Change the code to read from `colonna_int`, and ship it.

6. Only after that, drop the old column:
   ```sql
   ALTER TABLE t DROP COLUMN colonna;
   ```

**Step 6 can't be undone.** Once you drop the column, the data comes back only if you restore from backup. Steps 1 to 5 leave the old column untouched, so you can still go back until then.
