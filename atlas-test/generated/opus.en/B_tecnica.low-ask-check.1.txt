Connection pool exhausted, not slow query. Middleware at `db/session.py:47` releases connection only on success path.

When handler raises exception, `release()` never reached; connection stays held until timeout. After few hundred failed requests pool empties, and every later request waits for free connection. That's why latency rises instead of immediate errors.

Fix: wrap acquisition in try/finally so release happens on error path too.

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Don't raise `pool_size` as fix. Looks like one, but only masks leak: pushes back moment pool empties without removing it. Raise `pool_size` only after fix is in, and only if real load calls for it.

To reproduce behaviour before and after change:

```
pytest tests/test_pool.py -k exhaustion -x
```
