Your connection pool is running dry. A slow query is not the cause.

**Cause:** The middleware at `db/session.py:47` releases the connection only when the request succeeds. When the handler raises an exception, `release()` never runs. That connection stays held until it times out. After a few hundred failed requests the pool is empty, and every later request waits for a free connection. This is why latency keeps rising instead of requests failing straight away.

**Fix:** Wrap the acquisition in `try/finally`. Then the connection is released on the error path too:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

**Don't raise `pool_size` first.** It looks like a fix, but it only hides the problem. A bigger pool takes longer to empty, and connections still leak. Raise `pool_size` only after the fix is in, and only if your real load needs it.

**Check it:** Run this before and after the change to reproduce the problem and confirm the fix:

```

```
