Connection pool exhaustion, not slow query. Leak in middleware `db/session.py:47`: connection released only on success path. Handler raises exception, `release()` never reached, connection held until timeout. Few hundred failed requests empty the pool. Every later request waits for a free connection. That's why latency rises instead of immediate errors.

**Fix:** wrap acquisition in try/finally, so release also runs on error path:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Raising `pool_size` doesn't fix it. Only delays the moment the pool empties; leak stays. Raise `pool_size` only after the fix is in, and only if real load calls for it.

Reproduce before and after the change:

```
pytest tests/test_pool.py -k exhaustion -x
```
