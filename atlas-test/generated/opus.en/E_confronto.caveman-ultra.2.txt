For a small project, use Postgres. Move to Redis when volume really needs it.

**Why Postgres fits:**
- `SELECT ... FOR UPDATE SKIP LOCKED` handles up to about 1,000 jobs per minute.
- The job goes in the same transaction as the data. If the write rolls back, the job rolls back too, so it never starts.
- Persistence is built in. If the process dies, the queue is still there.
- It runs on the database you already have, so there's no new service.

**What Redis costs you:**
- It's one more service to run, monitor and upgrade.
- You have to set up persistence yourself. Without AOF enabled, a restart loses the queued jobs.

**Where Redis wins:** it handles far more volume, with latency under 1 ms. That only pays off once you go well past about 1,000 jobs per minute.
