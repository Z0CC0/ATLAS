internal knowledge

HTTPS: HTTP inside TLS-encrypted channel.

1. Client opens connection, lists TLS versions and ciphers it supports.

2. Server picks cipher and version, sends its certificate.

3. Client verifies certificate signature, walking chain up to root it already holds.

4. Client and server agree session key, today typically via elliptic curve Diffie-Hellman exchange.

5. From then on, traffic encrypted and authenticated: nobody in middle can read or modify it.

Certificate binds domain name to public key, signed by certificate authority. Says nothing about who runs site, **only that domain controls that key**.

Session key symmetric: asymmetric encryption costs too much for real traffic.

TLS 1.3 handshake: one round trip. TLS 1.2: two.
