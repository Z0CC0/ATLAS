Wrap the connection acquisition in `try/finally` in `db/session.py:47`:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

## What's happening

The connection pool is running out. A slow query is not the cause.

1. The middleware at `db/session.py:47` releases the connection only when the handler succeeds.
2. When the handler raises an exception, `release()` never runs. The connection stays held until it times out.
3. After a few hundred failed requests, the pool is empty. Every request after that waits for a free connection.
4. That's why latency keeps rising instead of requests failing right away: they're queuing for connections that aren't coming back.

With `finally`, the connection is released on the error path as well as the success path, so the leak stops.

## Don't just raise `pool_size`

A bigger pool looks like a fix, but it only hides the problem. It delays the moment the pool runs out, and connections still leak on every failed request. Raise `pool_size` only after the fix is in, and only if your real load needs it.
