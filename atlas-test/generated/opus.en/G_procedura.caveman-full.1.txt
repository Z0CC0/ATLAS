Don't use `ALTER TABLE ... ALTER COLUMN TYPE` directly. It rewrites the whole table while holding an `ACCESS EXCLUSIVE` lock, so your service is down until the rewrite finishes. Change the column in six steps instead:

1. **Check that every value converts.** Count the rows in `colonna` that are not all digits. If the count isn't zero, fix those rows before you go on.

2. **Add the new column.**
   ```sql
   ALTER TABLE t ADD COLUMN colonna_int integer;
   ```

3. **Fill the new column in batches of 10,000 rows.** Small batches mean no long lock is held on the table, so traffic keeps flowing.

4. **Add a trigger that keeps `colonna` and `colonna_int` in step** until the migration ends. Writes that arrive during and after the backfill then reach both columns.

5. **Change your code to read from `colonna_int`, and ship it.**

6. **Only after step 5 is live, drop the old column.**

> **Warning:** This step can't be undone. Once you drop `colonna`, its data comes back only if you restore from backup.
> ```sql
> ALTER TABLE t DROP COLUMN colonna;
> ```
