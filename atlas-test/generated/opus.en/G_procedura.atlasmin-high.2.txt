Don't run `ALTER TABLE ... ALTER COLUMN TYPE` directly. It rewrites the whole table while holding an ACCESS EXCLUSIVE lock, so the service is down for as long as the rewrite takes. Move the data to a new column in six steps, in this order:

1. Check that every existing value converts. Count the rows that are not all digits; the count must be zero before you go on:
   ```sql
   SELECT count(*) FROM t WHERE colonna !~ '^[0-9]+$';
   ```

2. Add the new column:
   ```sql
   ALTER TABLE t ADD COLUMN colonna_int integer;
   ```

3. Fill `colonna_int` in batches of 10,000 rows so no long lock is held on the table.

4. Add a trigger that keeps the two columns in step for the rest of the migration.

5. Change the code to read from `colonna_int`, then ship it.

6. Only after step 5 is live, drop the old column:
   ```sql
   ALTER TABLE t DROP COLUMN colonna;
   ```

**Step 6 can't be undone.** Once you drop the column, the data comes back only from a backup restore.
