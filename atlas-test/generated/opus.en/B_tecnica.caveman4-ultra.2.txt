Connection pool exhaustion, not slow query.

**Cause:** middleware `db/session.py:47` releases connection only on success path. Handler raises exception, `release()` never reached, connection held until timeout. After few hundred failed requests, pool empty, every later request waits. Hence rising latency, not immediate errors.

**Fix:** wrap acquisition in `try/finally`, so release happens on error path too:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

**Don't raise `pool_size` first.** Looks like fix, only masks it: pool empties later, leak stays. Raise only after fix is in, and only if real load calls for it.

**Reproduce before and after change:**

```
pytest tests/test_pool.py -k exhaustion -x
```
