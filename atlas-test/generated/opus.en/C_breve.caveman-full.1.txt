Usually no. On a column with only three distinct values, the planner normally ignores a plain B-tree index. If the filter matches more than roughly 5-10% of rows, the planner picks a sequential scan instead. With three values, most filters match far more than that, so the index sits unused. You still pay for it on every write, and it still takes disk space.

**Exception:** one value is rare and you query for that value. A partial index on only the rare value works well, because it stays small and the planner uses it:

```sql
CREATE INDEX orders_failed_idx ON orders (id) WHERE status = 'failed';
```

Skip the full index. Add a partial index only for the rare value you filter on.
