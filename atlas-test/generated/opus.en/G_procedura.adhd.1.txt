Start by counting the rows that won't convert. If the count is not 0, fix those rows before you go further:

```sql
SELECT count(*) FROM t WHERE colonna !~ '^[0-9]+$';
```

Don't run `ALTER TABLE t ALTER COLUMN colonna TYPE integer` directly. It rewrites the whole table while holding an `ACCESS EXCLUSIVE` lock, so the service is down until it finishes. Use these steps instead:

1. **Check:** run the count above. Continue only when it returns 0.
2. **Add the new column:**
   ```sql
   ALTER TABLE t ADD COLUMN colonna_int integer;
   ```
3. **Add a trigger** that keeps `colonna` and `colonna_int` in step. Rows written while you backfill then stay correct.
4. **Backfill in batches of 10,000 rows.** Small batches mean no long lock is ever held on the table.
5. **Switch the code** to read from `colonna_int`, then ship it.
6. **Only then, drop the old column:**
   ```sql
   ALTER TABLE t DROP COLUMN colonna;
   ```

⚠️ Step 6 can't be undone. Once you drop the column, the data comes back only from a backup restore. Don't run it until the new code is live and reading from `colonna_int`.
