Prompt caching saves the part of a request that has already been processed (the prefix). Later requests that start the same way don't pay to process it again.

It only works on the prefix. If a single character differs near the start, nothing from that point on is reused. So put the stable parts first and the parts that change after them, never the other way round.

Writing to the cache costs more than a normal read, so the first request is more expensive. The savings start with the second request and grow with each turn.

**It pays off** in long conversations with a large context that stays the same: system instructions, attached documentation and tool definitions.

**It doesn't pay off** for single requests that differ from each other. You pay for the write and never read it back.

Watch for one common trap: a line in the system prompt that changes every turn, such as a clock. It breaks reuse of everything that comes after it.
