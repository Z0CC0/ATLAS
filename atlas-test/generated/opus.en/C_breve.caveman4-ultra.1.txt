Usually no. B-tree index on a column with only 3 distinct values normally goes unused. If the filter selects more than roughly 5–10% of rows, the planner picks a sequential scan instead. You still pay for the index in slower writes and extra disk space.

Exception: if one value is rare, a partial index on that value does work:

```sql
CREATE INDEX orders_failed_idx ON orders (status) WHERE status = 'failed';
```

Queries with `WHERE status = 'failed'` use it.
