Don't use `ALTER TABLE t ALTER COLUMN colonna TYPE integer`. It rewrites the whole table while holding an `ACCESS EXCLUSIVE` lock, so the service is down for as long as the rewrite takes. Do the change in steps instead, in this order:

1. **Check that every value converts.** Count the rows that are not all digits, for example `SELECT count(*) FROM t WHERE colonna !~ '^[0-9]+$';`. Only continue when the count is 0.
2. **Add the new column:**
   ```sql
   ALTER TABLE t ADD COLUMN colonna_int integer;
   ```
3. **Fill it in batches of 10,000 rows.** Small batches mean no long lock is held on the table.
4. **Add a trigger** that keeps `colonna` and `colonna_int` in step while the migration runs.
5. **Change the code** to read from `colonna_int`, and ship it.
6. **Only then drop the old column:**
   ```sql
   ALTER TABLE t DROP COLUMN colonna;
   ```

**Warning:** step 6 can't be undone. Once the column is dropped, the data only comes back by restoring from backup. Make sure step 5 is running correctly in production before you do it.
