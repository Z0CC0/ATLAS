HTTPS is HTTP inside a channel encrypted by TLS.

1. Client opens connection, lists TLS versions and ciphers it supports.

2. Server picks cipher and version, sends its certificate.

3. Client checks certificate signature, walking chain up to root it already holds.

4. Client and server agree session key, today usually through elliptic curve Diffie-Hellman exchange.

5. From then on, traffic encrypted and authenticated: anyone in the middle can neither read nor modify it.

Certificate binds domain name to public key, signed by certificate authority. It says nothing about who runs the site, only that the domain controls that key.

Session key symmetric: asymmetric encryption costs too much for real traffic.

TLS 1.3 handshake takes a single round trip; TLS 1.2 takes two.
