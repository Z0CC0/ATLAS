HTTPS is HTTP running inside a channel encrypted by TLS. Setting up that channel works like this:

1. The client opens the connection and lists the TLS versions and ciphers it supports.

2. The server picks a version and a cipher, then sends its certificate.

3. The certificate binds a domain name to a public key and is signed by a certificate authority. The client checks that signature by following the chain up to a root certificate it already holds.

4. The client and server agree on a session key, today usually with an elliptic curve Diffie-Hellman exchange. The session key is symmetric because asymmetric encryption is too expensive for real traffic.

5. From then on, all traffic is encrypted and authenticated. Anyone in the middle can neither read it nor change it.

TLS 1.3 completes this handshake in one round trip, while TLS 1.2 needs two.

The certificate does **not** say who runs the site. It only proves that the domain controls that key.
