Prompt caching stores the already-processed prefix of a request. Later requests that start the same way don't pay to process that prefix again.

It only works on the prefix. If one character differs near the start, nothing is reused from that point on.

So put stable parts first and changing parts after them, never the other way round.

A system line that changes every turn, such as a clock, breaks reuse of everything after it.

Writing to the cache costs more than a normal read, so the first request is more expensive.

The savings start with the second request and grow with each turn.

It pays off in long conversations with a large stable context: system instructions, attached documentation, tool definitions.

It doesn't pay off for one-off requests that differ from each other. You pay for the write and never read it back.
