Prompt caching stores the already-processed start (prefix) of a request, so later requests that begin the same way don't pay for that part again.

It only works on the prefix. If one character at the start is different, nothing is reused from that point on. So put the stable parts first and the changing parts after, never the other way round.

Writing to the cache costs more than a normal read, so the first request is more expensive. The savings start with the second request and grow with the number of turns.

It pays off on long conversations with a large stable context, such as system instructions, attached documentation and tool definitions.

It doesn't pay off on single requests that differ from each other. You pay for the cache write and never read it back.

Watch out for a system line that changes every turn, such as a clock. It stops everything after it from being reused.
