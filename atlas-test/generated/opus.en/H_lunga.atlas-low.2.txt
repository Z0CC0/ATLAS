Prompt caching saves the part of a request that has already been processed, called the prefix. Later requests that start the same way don't pay to process that part again.

It only works on the prefix. If even one character near the start differs, nothing from that point on can be reused.

So put stable parts first and changing parts after, never the other way round. A system line that changes every turn, such as a clock, stops reuse of everything after it.

Writing to the cache costs more than a normal read, so your first request costs more. Savings start with the second request and grow with each turn.

It pays off on long conversations with a large context that stays the same: system instructions, attached documentation, tool definitions.

It doesn't pay off when you send single requests that all differ. You pay for the write and never read it back.
