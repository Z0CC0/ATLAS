Prompt caching saves the part of a request that stays the same between calls, so you only pay for it once. It pays off when many requests share a large stable beginning.

The cache keeps the already-processed prefix of a request. Any later request that starts the same way doesn't pay to process that part again. Reuse works only on the prefix: if one character differs near the start, nothing from that point on is reused.

So order matters. Put the stable parts first and the parts that change after them, never the other way round. A line near the top that changes every turn, such as a clock in the system prompt, stops reuse of everything after it.

Writing to the cache costs more than a normal read, so the first request is more expensive. You start saving from the second request, and the savings grow with each turn.

**When it pays off:** long conversations with a large stable context, such as system instructions, attached documentation and tool definitions. That context is written once and then read on every turn.

**When it doesn't:** single requests that differ from each other. You pay the extra cost of writing to the cache and never read it back.
