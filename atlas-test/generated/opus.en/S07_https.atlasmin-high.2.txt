HTTPS is ordinary HTTP carried inside a channel that TLS encrypts.

Connection setup, in order:

1. The client opens the connection and lists the TLS versions and ciphers it supports.

2. The server picks a cipher and a version, then sends its certificate.

3. The client checks the certificate's signature by following the chain up to a root certificate it already holds.

4. Client and server agree on a session key, today usually through an elliptic curve Diffie-Hellman exchange.

5. From then on, traffic is encrypted and authenticated. Anyone in the middle can neither read it nor change it.

The certificate ties a domain name to a public key. A certificate authority signs it.

The session key is symmetric because asymmetric encryption costs too much for real traffic.

TLS 1.3 completes the handshake in one round trip. TLS 1.2 needs two.

The certificate says **nothing about who runs the site**. It only proves that the domain controls that key.
