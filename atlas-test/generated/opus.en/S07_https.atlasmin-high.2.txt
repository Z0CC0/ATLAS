HTTPS is HTTP sent inside a channel that TLS encrypts.

Handshake, in order:

1. Client opens the connection and lists the TLS versions and ciphers it supports.
2. Server picks a version and a cipher, and sends its certificate.
3. Client checks the certificate's signature by walking the chain up to a root certificate it already holds.
4. Client and server agree on a session key, today usually with an elliptic curve Diffie-Hellman exchange.

Certificate: binds a domain name to a public key, signed by a certificate authority. It says nothing about who runs the site, only that the domain controls that key.

Session key is symmetric, because asymmetric encryption costs too much for real traffic.

After the handshake, traffic is encrypted and authenticated. Anyone in the middle can neither read it nor modify it.

TLS 1.3 needs one round trip for the handshake. TLS 1.2 needs two.
