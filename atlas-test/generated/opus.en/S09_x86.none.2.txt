# How x86 evolved, from the 8086 to today

## The starting point: the 8086 (1978)

The story actually starts a little before the eighties. The 8086 came out in 1978 as a 16-bit processor. It grew out of the 8080 and was compatible with it at the source level, so existing code could be carried over. That decision set the pattern for everything that followed: each new x86 generation had to keep running the software written for the ones before it.

## Learning to protect itself: the 80286 (1982)

The 80286 added **protected mode**, which gave the processor a way to keep programs separate from one another. It had a serious flaw, though. Once the chip switched into protected mode, it could only get back to the old real mode by rebooting. For a platform that depended on running older software, that was a real obstacle.

## The 80386 (1985): the architecture takes its lasting shape

The 80386 is where x86 took the form it would keep for the next twenty years. It brought three things:
- **32-bit** processing
- **Paged virtual memory**, which is the basis of how modern operating systems manage memory
- **Virtual 8086 mode**, which let old real-mode programs run inside the protected environment. This solved the 286's problem without any need to reboot.

## Moving parts onto the chip: the 486 (1989)

The 486 took parts that used to sit outside the processor and built them into it: the **first-level cache** and the **maths coprocessor**. Both now lived on the same chip as the CPU.

## Running instructions in parallel: the Pentium (1993)

The Pentium was **superscalar**. It had two integer pipelines and could complete two instructions in a single clock cycle. The goal was no longer only to run each instruction faster, but to run more than one at once.

## The big change: the Pentium Pro (1995)

The Pentium Pro is the turning point of the whole story. It introduced **out-of-order execution**, and it translated x86 instructions into internal **micro-operations** before executing them.

From then on, x86 was an interface rather than the actual machine. The instruction set programmers write for is a contract, and the hardware underneath is free to work completely differently, as long as it keeps that contract. Everything after this point follows from that.

## A dead end: the Pentium 4 (2000)

The Pentium 4 tried to win by raising the clock frequency, using a very long pipeline to get there. It ran into the **power wall**: past a certain point, higher frequency simply uses too much power to be practical.

## Someone else leads: AMD64 (2003)

The move to 64 bit came from AMD, not Intel. AMD extended the architecture with **AMD64** in 2003, and Intel then adopted the same instruction set. This was the first time the extension that became the standard didn't come from Intel.

## More cores instead of more speed: Core 2 (2006)

After the power wall, the industry changed direction. Starting with the Core 2 in 2006, progress came from putting **more cores** on a chip rather than raising the frequency.

## Vector extensions, running alongside

Throughout these generations, the vector extensions kept growing, which let one instruction work on many pieces of data at once:
**MMX → SSE → AVX → AVX-512**

## Today: the complexity is underneath

The visible instruction set is no longer where most of the engineering happens. The hard work is in the layers below it: **branch prediction**, the **cache hierarchy**, and **speculative execution**, all of which keep the processor busy by guessing what comes next.

## The cost: Spectre and Meltdown (2018)

In 2018, Spectre and Meltdown showed that speculative execution had a security cost nobody had accounted for. The technique that had made processors faster for decades turned out to leak information.

---

**In short:** x86 began as a direct description of the hardware. With the Pentium Pro in 1995 it became a compatibility layer on top of hardware that works very differently. Since then, performance has come from frequency, then from more cores, and from increasingly aggressive work hidden below that layer. As Spectre and Meltdown showed, that hidden work can have costs that only become visible years later.
