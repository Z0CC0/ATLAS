Connection pool exhaustion, not a slow query.

Middleware at `db/session.py:47` releases connection only on success path. When handler raises exception, `release()` never runs, so connection stays held until timeout. After a few hundred failed requests, pool empties and every later request waits for a free connection. That's why you see rising latency instead of immediate errors.

Fix: wrap acquisition in try/finally so release also happens on error path:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Raising `pool_size` looks like a fix but only masks the leak. It delays the moment the pool empties without removing the leak. Raise it only after the fix is in, and only if real load calls for it.

To reproduce the behaviour before and after the change:

```
pytest tests/test_pool.py -k exhaustion -x
```
