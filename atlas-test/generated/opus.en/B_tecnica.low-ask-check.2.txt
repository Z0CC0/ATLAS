Connection pool exhaustion, not slow query. Connections leak on the error path.

Middleware at `db/session.py:47` releases the connection only on the success path. When handler raises an exception, `release()` never reached, so connection stays held until timeout. After a few hundred failed requests, pool empties and every later request waits for a free connection. That's why latency keeps rising instead of requests failing immediately.

Fix: wrap acquisition in try/finally so release happens on the error path too:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Don't raise `pool_size` as the fix. It only masks the problem: pool empties later, but the leak stays. Raise it only after the fix is in, and only if real load calls for it.

To reproduce the behaviour before and after the change:

```
pytest tests/test_pool.py -k exhaustion -x
```
