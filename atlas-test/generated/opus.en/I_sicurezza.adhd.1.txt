No. Move the key to your server and have the frontend call your own backend.

Obfuscation doesn't protect it. Anything that reaches the browser can be read. Someone only has to open the developer tools or look at the network requests to see the key.

**What to do:**

1. Store the key on your server only.
2. Add a backend endpoint. The frontend calls that endpoint, and the endpoint calls the service using the key.
3. Put a rate limit on that endpoint. Without one, anyone can use it to spend your key for free.

**If the key has already been published** (in a deployed frontend or a pushed commit):

1. Treat it as compromised. Rotate it at the service right away.
2. Then remove it from the code.

Deleting it from a commit isn't enough. The key stays in the repository history, and anyone who already cloned the repo has it. Only rotating it makes the old key useless.
