Don't change the type in place. Add a new integer column, move the data over, and drop the old column only at the end. A direct `ALTER TABLE ALTER COLUMN TYPE` rewrites the whole table while holding an ACCESS EXCLUSIVE lock, so your service would be down for the whole rewrite.

Do these steps in this order:

1. Check that every existing value can be converted. Count the rows whose value is not all digits. The count must be zero before you go on:
   ```sql
   SELECT count(*) FROM t WHERE colonna !~ '^[0-9]+$';
   ```

2. Add the new column:
   ```sql
   ALTER TABLE t ADD COLUMN colonna_int integer;
   ```

3. Fill `colonna_int` in batches of 10,000 rows, so no single statement holds a long lock on the table.

4. Add a trigger that keeps the two columns in step while the migration runs, so rows written during the backfill also end up in `colonna_int`.

5. Change the code to read from `colonna_int`, and ship it.

6. Only after that, drop the old column:
   ```sql
   ALTER TABLE t DROP COLUMN colonna;
   ```

**Step 6 can't be undone.** Once you drop the column, the data comes back only through a restore from backup. Run it only after the code reading `colonna_int` is live and working.
