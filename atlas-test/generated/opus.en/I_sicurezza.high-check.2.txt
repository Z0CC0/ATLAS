No. Anything that reaches the browser can be read, and obfuscation stops working as soon as someone opens the developer tools or looks at the network requests.

Keep the key on your server instead. The frontend calls an endpoint on your own backend, and that endpoint calls the service with the key.

Put a rate limit on that endpoint. Without one, anyone can use it to spend your key for free.

If the key has already been published, treat it as compromised and rotate it right away. Removing it from the code is not enough. Deleting it from a commit doesn't help either, because it stays in the repository history and anyone who already has a clone has the key.
