internal knowledge

Cache stores already-processed prefix of request; later requests starting same way skip paying for it again.

Prefix only: one different character at start, no reuse from that point on. So stable parts first, changing parts after, never reverse.

Cost: cache write pricier than normal read, so first request costs more. Gain starts from second request, grows with number of turns.

Pays off: long conversations with large stable context, such as system instructions, attached documentation, tool definitions.

Doesn't pay off: single requests differing from each other. You pay write, never read it back.

Common trap: system line changing every turn, such as clock, kills reuse of everything after it.
