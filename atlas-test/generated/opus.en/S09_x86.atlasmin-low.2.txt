x86 evolved in three stages. First Intel added capability to the instruction set. Then the instruction set turned into an interface over a different machine underneath. Since then, most of the progress has come from the hardware layers under that interface.

**Foundations (1978–1989)**

8086 of 1978: 16 bit, grown out of 8080 and compatible with it at source level. That compatibility set the pattern for everything after.

80286 of 1982 introduced protected mode, but with a flaw: no way back to real mode without a reboot.

80386 of 1985 brought 32 bit, paged virtual memory and virtual 8086 mode, so old real-mode software could run inside the protected environment. Roughly the architecture still recognisable today.

486 of 1989 pulled first level cache and maths coprocessor onto the chip.

**The real machine goes underground (1993–2000)**

Pentium of 1993: superscalar, two integer pipelines able to retire two instructions per cycle.

Pentium Pro of 1995 was the deeper break. It introduced out of order execution and translated x86 instructions into internal micro-operations. From that point x86 became an interface, no longer the real machine underneath.

Pentium 4 of 2000 chased frequency with a very long pipeline and hit the power wall. Raising clock speed stopped being a viable path.

**New directions (2003–today)**

In 2003 AMD extended the architecture to 64 bit with AMD64, and Intel adopted the same instruction set. First time the dominant extension did not come from Intel.

From 2006, with Core 2, the direction shifted from frequency to core count.

Vector extensions grew across generations: MMX, SSE, AVX, AVX-512.

Today the complexity sits in the layers below the instruction set: branch prediction, cache hierarchy, speculative execution. In 2018, Spectre and Meltdown showed that speculative execution carried a security cost nobody had priced.
