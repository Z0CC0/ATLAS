HTTPS = HTTP inside a channel encrypted by TLS.

**Handshake:**
1. Client opens connection and lists the TLS versions and ciphers it supports.
2. Server picks a cipher and a version, then sends its certificate.
3. Certificate binds a domain name to a public key and is signed by a certificate authority (CA). Client checks that signature by walking the chain up to a root certificate it already holds.
4. Client and server agree on a session key. Today this is usually an elliptic curve Diffie-Hellman exchange.

**Why the session key is symmetric:** asymmetric encryption costs too much for real traffic. Public key used only during setup.

**After handshake:** traffic encrypted and authenticated. Anyone in the middle can't read it or modify it.

**Speed:** TLS 1.3 handshake takes one round trip. TLS 1.2 takes two.

**Limit:** certificate says nothing about who runs the site. It says only that the domain controls that key.
