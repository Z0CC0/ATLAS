# How x86 evolved, from the 8086 to today

## Where it started: the 8086 (1978)

The story starts a little before the eighties, with the 8086 in 1978. It was a 16-bit processor that grew out of the 8080, and it was compatible with the 8080 at source level. Old code couldn't run unchanged, but it could be carried over. That choice to stay continuous with what came before became the habit that shaped everything after it.

## Protection and 32 bits: the 80286 and 80386

The **80286** (1982) introduced *protected mode*, the first serious step toward supporting a real operating system. The implementation had a flaw: once the chip entered protected mode, the only way back to real mode was a reboot. That was a problem for a platform whose value depended on running old software.

The **80386** (1985) fixed it and went further. It brought:
- **32-bit** operation
- **paged virtual memory**
- **virtual 8086 mode**, which let old real-mode programs run inside the protected environment instead of forcing a choice between the two

The 386 set the shape of x86 for the next two decades.

## Integration and parallelism: the 486 and Pentium

The **486** (1989) moved the first-level cache and the maths coprocessor onto the chip. Both had been separate parts before. Putting them on the die made them faster and tied them closely to the core.

The **Pentium** (1993) was **superscalar**. It had two integer pipelines and could retire two instructions per cycle. This marked a shift from making one instruction faster to doing more than one at a time.

## The turning point: the Pentium Pro (1995)

The **Pentium Pro** was the deepest change in the line. It introduced **out-of-order execution**, and it translated x86 instructions into internal **micro-operations** that the hardware actually executes.

From then on, x86 is an *interface*: a contract with software, not the real machine underneath. Programs still speak x86, but the processor rewrites that into its own internal form and schedules it as it sees fit. Everything that follows builds on this split.

## The frequency race and the power wall: the Pentium 4 (2000)

With the instruction set separated from the hardware, the next push was clock speed. The **Pentium 4** used a very long pipeline so it could run at very high frequencies. It ran into the **power wall**: past a certain point, raising the frequency costs more power and heat than the chip can handle.

## 64 bits, from an unexpected source: AMD64 (2003)

In 2003 **AMD** extended the architecture to 64 bits with **AMD64**, and Intel adopted the same instruction set. For the first time, the dominant extension to x86 came from someone other than Intel.

## From faster to wider: the Core 2 (2006)

After the power wall, the industry changed direction. From 2006, starting with the **Core 2**, the goal moved from higher frequency to **more cores**: several processors on one chip instead of one processor running ever faster.

Alongside this, the **vector extensions** grew generation by generation: **MMX**, then **SSE**, then **AVX**, then **AVX-512**. Each one lets a single instruction work on more data at once.

## Today: the complexity is underneath

The visible instruction set is now the least interesting part. The real engineering is in the layers below:
- **branch prediction**, which guesses where the code will go next
- the **cache hierarchy**, which keeps data close to the cores
- **speculative execution**, which does work before the processor knows whether it will be needed

## The bill arrives: Spectre and Meltdown (2018)

Speculative execution was one of the main sources of performance, and in 2018 **Spectre** and **Meltdown** showed it had a security cost nobody had accounted for. Work the processor did speculatively and then threw away could still leave traces that an attacker could read. The hidden machinery that had made x86 fast for decades turned out to be a security risk as well.

## The arc in one line

x86 went from a 16-bit chip that was simply what it appeared to be, through protection, 32 bits, integration and parallelism, to a compatibility interface on top of a very complex speculative engine. Its outward compatibility stayed fixed while almost everything underneath it was replaced.
