Don't change the type in place. Add a new integer column, move the data across in steps, and drop the old column last. A direct `ALTER TABLE ... ALTER COLUMN ... TYPE integer` rewrites the whole table while holding an ACCESS EXCLUSIVE lock, so the service is down for as long as the rewrite takes.

1. Check that every existing value can be converted by counting the rows that are not all digits. If the count isn't zero, fix those rows before you go on.

2. Add the new column:
```sql
ALTER TABLE t ADD COLUMN colonna_int integer;
```

3. Fill it in batches of ten thousand rows, so no long lock is held on the table.

4. Add a trigger that keeps the two columns in step while the migration runs, so rows written during the migration also get the integer value.

5. Change the code to read from the new column, and ship it.

6. Only after all of that, drop the old column:
```sql
ALTER TABLE t DROP COLUMN colonna;
```

**Step 6 can't be undone.** Once the column is dropped, the data only comes back through a restore from backup. Don't run it until the code reading `colonna_int` is live and working.
