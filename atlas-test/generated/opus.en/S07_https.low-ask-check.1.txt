internal knowledge

HTTPS: HTTP inside channel encrypted by TLS. Before any page travels, client and server run a handshake:

1. Client opens connection, states which TLS versions and ciphers it supports.

2. Server answers, picking cipher and version, and sends its certificate.

3. Certificate binds domain name to public key, signed by certificate authority. Client verifies signature by walking chain up to root it already holds.

4. Client and server agree session key, today typically with elliptic curve Diffie-Hellman exchange.

Session key symmetric because asymmetric encryption costs too much for real traffic. From that point, traffic encrypted and authenticated: nobody in the middle can read or modify it.

TLS 1.3 cuts handshake to single round trip, against two in TLS 1.2.

One limit: certificate says nothing about who runs site. It says only that domain controls that key.
