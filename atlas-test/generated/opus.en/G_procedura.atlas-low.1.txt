Don't run `ALTER TABLE ... ALTER COLUMN ... TYPE` directly. It rewrites the whole table while holding an ACCESS EXCLUSIVE lock, so the service is down for the entire rewrite. Move the data to a new column in stages instead:

1. Check that every existing value can be converted. Count the rows where `colonna` is not all digits. If the count isn't zero, fix those rows before you go on.

2. Add the new column:
   ```sql
   ALTER TABLE t ADD COLUMN colonna_int integer;
   ```

3. Fill `colonna_int` in batches of 10,000 rows, so no long lock is held on the table.

4. Add a trigger that keeps the two columns in step while the migration runs. Rows written or updated during the backfill then stay consistent.

5. Change the code to read from `colonna_int`, and ship it.

6. Only after the new code is live and working, drop the old column:
   ```sql
   ALTER TABLE t DROP COLUMN colonna;
   ```

**Step 6 can't be undone.** Once you drop the column, its data comes back only by restoring from a backup. Do not run it until steps 1 to 5 are finished and the service is reading from the new column without problems.
