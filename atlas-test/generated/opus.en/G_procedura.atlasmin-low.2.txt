Don't use a direct `ALTER TABLE ... ALTER COLUMN ... TYPE`. It rewrites the whole table while holding an ACCESS EXCLUSIVE lock, so the service is down for as long as the rewrite takes. Migrate in steps instead:

1. Make sure every existing value can be converted. Count the rows whose value is not all digits. If the count isn't zero, fix those rows before you go on.

2. Add the new column:
   ```sql
   ALTER TABLE t ADD COLUMN colonna_int integer;
   ```

3. Fill it in batches of 10,000 rows, so the table is never locked for long.

4. Add a trigger that keeps the two columns in step while the migration runs, so rows written during the backfill stay correct.

5. Change the code to read from `colonna_int` and ship it.

6. Only after that, drop the old column:
   ```sql
   ALTER TABLE t DROP COLUMN colonna;
   ```

You can't undo step 6. Once the column is dropped, the only way to get its data back is a restore from backup. Before you run it, make sure the new code is live and reading from `colonna_int`.
