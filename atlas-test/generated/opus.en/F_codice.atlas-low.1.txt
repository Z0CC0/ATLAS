Wrap function in closure holding one timer; each call cancels previous timer and starts new one, so `fn` runs only after `ms` of silence.

```js
function debounce(fn, ms) {
  let t;
  return (...args) => {
    clearTimeout(t);
    t = setTimeout(() => fn(...args), ms);
  };
}
```

Three details matter.

`clearTimeout(t)` must run before every new `setTimeout`. Otherwise timers pile up and function fires more than once.

`t` lives in closure, not inside returned function. Declared inside, every call would get its own timer and no debouncing would happen.

`...args` forwards arguments. Without spread, called function receives nothing.

This version returns nothing. If return value matters, you need Promise.

For opposite behavior, running immediately and then ignoring calls for period, you want throttle, which is different function.
