Connection pool exhaustion, not slow query.

**Cause:** Middleware at `db/session.py:47` releases connection only on success path. Handler raises exception, `release()` never reached. Connection stays held until timeout. After few hundred failed requests, pool empties. Every later request waits for free connection. That is why latency rises instead of immediate errors.

**Fix:** Wrap acquisition in `try/finally`. Release then runs on error path too:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

**Not fix:** Raising `pool_size`. Only masks leak: pushes back moment pool empties, leak stays. Raise `pool_size` only after fix is in, only if real load needs it.

**Verify:** Run before and after change to reproduce behaviour:

```
pytest tests/test_pool.py -k exhaustion -x
```
