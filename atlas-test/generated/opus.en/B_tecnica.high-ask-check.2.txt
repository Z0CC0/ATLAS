Connection pool exhaustion, not slow query.

Cause: middleware `db/session.py:47` releases connection only on success path. Handler raises exception → `release()` never reached, connection held until timeout. After few hundred failed requests pool empties, every later request waits. Hence rising latency instead of immediate errors.

Fix: wrap acquisition in try/finally so release also happens on error path:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Do not raise `pool_size` as fix. Only masks leak: delays moment pool empties, connections still leak. Raise it only after fix is in, and only if real load calls for it.

Reproduce before and after change:

```
pytest tests/test_pool.py -k exhaustion -x
```
