HTTPS is HTTP inside a channel encrypted by TLS.

Handshake:

1. Client opens connection and lists the TLS versions and ciphers it supports.

2. Server picks a cipher and version, then sends its certificate.

3. Client checks the certificate's signature by walking the chain up to a root it already holds.

4. Both sides agree a session key, today usually through an elliptic curve Diffie-Hellman exchange.

The certificate binds a domain name to a public key and is signed by a certificate authority. It says nothing about who runs the site, only that the domain controls that key.

The session key is symmetric because asymmetric encryption costs too much for real traffic.

After the handshake, traffic is encrypted and authenticated. Nobody in the middle can read or modify it.

TLS 1.3 needs only one round trip for the handshake. TLS 1.2 needs two.
