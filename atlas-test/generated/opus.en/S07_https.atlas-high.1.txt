HTTPS is HTTP running inside a channel encrypted by TLS.

The connection is set up with a handshake:

1. The client opens the connection and lists the TLS versions and ciphers it supports.

2. The server picks a cipher and a version, then sends its certificate.

3. The client checks the certificate's signature by following the chain up to a root certificate it already holds.

4. The client and server agree on a session key, today usually through an elliptic curve Diffie-Hellman exchange.

5. From then on, all traffic is encrypted and authenticated. Anyone in the middle can't read it or change it.

A certificate links a domain name to a public key, and a certificate authority signs it. It doesn't say who runs the site. It only says that the domain controls that key.

The session key is symmetric because asymmetric encryption costs too much for real traffic.

The TLS 1.3 handshake takes only one round trip. TLS 1.2 takes two.
