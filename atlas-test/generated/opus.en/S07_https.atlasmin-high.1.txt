HTTPS is ordinary HTTP carried inside a channel that TLS encrypts.

The connection starts with a handshake:

1. The client opens the connection and says which TLS versions and ciphers it supports.

2. The server picks a version and a cipher, and sends its certificate.

3. The client checks the certificate's signature by following the chain of certificate authorities up to a root certificate it already holds.

4. Client and server agree on a session key. Today this is usually done with an elliptic curve Diffie-Hellman exchange.

5. From then on, all traffic is encrypted and authenticated. Anyone in the middle can neither read it nor change it.

The certificate links a domain name to a public key, and a certificate authority signs it. It says nothing about who runs the site. It only shows that whoever controls the domain controls that key.

The session key is symmetric because asymmetric encryption costs too much for real traffic.

TLS 1.3 needs only one round trip for the handshake. TLS 1.2 needs two.
