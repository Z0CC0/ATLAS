HTTPS is HTTP sent through a channel that TLS encrypts. Before any HTTP is sent, the client and server set that channel up with a handshake:

1. The client opens the connection and lists the TLS versions and ciphers it supports.

2. The server picks a cipher and a version and sends its certificate. The certificate binds a domain name to a public key, and a certificate authority signs it.

3. The client checks that signature by following the chain of certificates up to a root certificate it already has.

4. The client and server agree on a session key. Today this is usually done with an elliptic curve Diffie-Hellman exchange.

The session key is symmetric because asymmetric encryption is too costly for real traffic.

After the handshake, all traffic is encrypted and authenticated. Anyone in the middle can't read it or change it.

TLS 1.3 does the handshake in one round trip. TLS 1.2 needs two.

A certificate doesn't tell you who runs the site. It only shows that whoever controls the domain also controls that key.
