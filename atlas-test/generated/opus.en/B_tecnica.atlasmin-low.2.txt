Your connection pool is running out because connections leak. A slow query is not the cause.

In the middleware at `db/session.py:47`, the connection gets released only when the request succeeds. When the handler raises an exception, `release()` is never reached, so that connection stays held until it times out.

After a few hundred failed requests the pool is empty, and every later request waits for a connection. That's why latency keeps rising instead of requests failing right away with errors.

To fix it, wrap the acquisition in try/finally so the connection is also released when the handler fails:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Don't raise `pool_size` as the fix. It only hides the problem: the pool takes longer to empty, but the leak is still there. Raise it only after the fix is in, and only if your real load needs it.

To reproduce the lockup, run this before and after the change:

```
pytest tests/test_pool.py -k exhaustion -x
```
