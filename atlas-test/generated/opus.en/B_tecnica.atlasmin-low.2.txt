Connection pool exhaustion, not slow query.

Middleware at `db/session.py:47` releases connection only on success path. When handler raises exception, `release()` never reached, so connection stays held until timeout. After a few hundred failed requests pool empties and every later request waits for a free connection. That's why you see rising latency instead of immediate errors.

Fix: wrap acquisition in try/finally so release happens on error path too:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Don't raise `pool_size` as the fix. It looks like one, but only masks the leak: it delays the moment the pool empties without removing it. Raise `pool_size` only after the fix is in, and only if real load calls for it.

To reproduce behaviour before and after the change:

```
pytest tests/test_pool.py -k exhaustion -x
```
