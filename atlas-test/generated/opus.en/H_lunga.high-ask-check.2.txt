internal knowledge

Cache keeps already-processed prefix of request, so later requests starting same way don't pay for it again.

Works only on prefix: one different character at start, no reuse from that point on.

So stable parts first, changing parts after, not other way round.

Cache write costs more than normal read, so first request is more expensive.

Gain starts from second request, grows with number of turns.

**Pays off:** long conversations with large stable context, such as system instructions, attached documentation, tool definitions.

**Doesn't pay off:** single requests that differ from each other. Write gets paid, never read back.

System line that changes every turn, such as clock, kills reuse of everything after it.
