No. Move the key to your server. Obfuscating it doesn't protect it. Anything the browser receives can be read. Someone opens the developer tools or looks at the network requests and has your key in seconds.

**What to do instead:**

1. Store the key on your backend only.
2. Add a backend endpoint that calls the service using the key.
3. Have the frontend call your own endpoint, never the service directly.
4. Put a rate limit on that endpoint. Without one, anyone can call it and use your key for free.

**If the key has already been published** (shipped in frontend code or pushed to a repo):

1. Rotate it now. Treat it as compromised. Removing it from the code isn't enough.
2. Deleting it in a new commit doesn't make it go away. The key stays in the repository history, and anyone who already cloned the repo has it. Rotating is the only real fix.

Next: if the key has ever been in the browser or a commit, open the service's dashboard and generate a new key. That takes about 2 minutes.
