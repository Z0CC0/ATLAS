HTTPS is HTTP running inside a channel that TLS encrypts.

The connection is set up in this order:

1. The client opens the connection and lists the TLS versions and ciphers it supports.
2. The server picks a cipher and a version, and sends its certificate.
3. The client checks the certificate's signature by following the chain up to a root certificate it already holds.
4. Client and server agree on a session key. Today this is usually done with an elliptic curve Diffie-Hellman exchange.
5. From then on, all traffic is encrypted and authenticated. Anyone in the middle can neither read it nor change it.

A certificate binds a domain name to a public key, and a certificate authority signs it.

The session key is symmetric because asymmetric encryption costs too much for real traffic.

TLS 1.3 completes the handshake in one round trip. TLS 1.2 needs two.

A certificate says nothing about who runs the site. It only says that the domain controls that key.
