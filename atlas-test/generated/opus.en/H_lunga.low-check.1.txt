internal knowledge

Prompt caching saves already-processed start (prefix) of request, so later requests beginning same way don't pay to process it again. It pays off on long conversations with large context that stays the same, and doesn't pay off on one-off requests that differ from each other.

**How it works:** reuse covers only prefix. One different character near start, and nothing from that point on gets reused. So stable parts go first and changing parts after, never other way round.

**Cost:** writing to cache costs more than normal read, so first request comes out more expensive. Savings start from second request and grow with each turn.

When it pays off: long conversations built on big stable block, such as system instructions, attached documentation and tool definitions. That block gets written once and read back on every turn.

When it doesn't: single requests that each differ. You pay for cache write and never read it back.

Common trap: line in system prompt that changes every turn, such as clock or timestamp. Everything after it stops being reused. Move it to end, or remove it.
