Don't run `ALTER TABLE ... ALTER COLUMN TYPE` directly. It rewrites the whole table while holding an ACCESS EXCLUSIVE lock, so your service is down for as long as the rewrite takes. Move the data to a new column in stages instead:

1. **Check every value converts.** Count the rows where `colonna` is not all digits. If the count is not zero, fix those rows before you continue.
2. **Add the new column:**
   ```sql
   ALTER TABLE t ADD COLUMN colonna_int integer
   ```
3. **Backfill in batches of 10,000 rows.** Small batches mean no long lock is held on the table.
4. **Add a trigger** that keeps `colonna` and `colonna_int` in step for the rest of the migration.
5. **Change your code to read from `colonna_int`,** then ship it.
6. **Only after step 5 is shipped, drop the old column:**
   ```sql
   ALTER TABLE t DROP COLUMN colonna
   ```

**Warning:** step 6 can't be undone. Once you drop the column, the only way to get that data back is to restore from a backup. Before you run it, confirm the new code is live and reads only from `colonna_int`.
