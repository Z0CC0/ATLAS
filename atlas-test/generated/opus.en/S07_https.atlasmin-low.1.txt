HTTPS is HTTP running inside a channel that TLS encrypts. Before any HTTP traffic is sent, client and server run a TLS handshake.

1. The client opens the connection and says which TLS versions and ciphers it supports.

2. The server picks a cipher and a version and sends back its certificate.

3. The client checks the certificate. A certificate binds a domain name to a public key, and a certificate authority signs it. The client verifies that signature by following the chain of certificates up to a root certificate it already has.

4. Client and server agree on a session key. Today this is usually done with an elliptic curve Diffie-Hellman exchange.

The session key is symmetric because asymmetric encryption is too expensive for real traffic. Asymmetric cryptography is only used to set up the connection.

After the handshake, all traffic is encrypted and authenticated. Anyone in the middle can't read it or change it.

TLS 1.3 completes the handshake in a single round trip. TLS 1.2 needs two.

A certificate says nothing about who runs the site. It only proves that whoever controls the domain also controls that key.
