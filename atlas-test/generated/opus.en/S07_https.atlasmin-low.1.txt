HTTPS is ordinary HTTP carried inside a channel that TLS encrypts. Before any HTTP is sent, client and server run a handshake:

1. The client opens the connection and says which TLS versions and ciphers it supports.

2. The server picks a version and a cipher, then sends its certificate. The certificate binds a domain name to a public key and is signed by a certificate authority.

3. The client checks that signature by following the chain of certificates up to a root certificate it already holds.

4. Client and server agree on a session key. Today this is usually done with an elliptic curve Diffie-Hellman exchange.

The session key is symmetric because asymmetric encryption costs too much for real traffic. Once the key is agreed, all traffic is encrypted and authenticated. Anyone in the middle can neither read it nor change it.

TLS 1.3 completes this handshake in one round trip. TLS 1.2 needs two.

A valid certificate only proves that whoever controls the domain also controls that key. **It says nothing about who runs the site.**
