internal knowledge

x86 began as a 16-bit design built on what came before, then over four decades turned into a compatibility layer on top of a much more complex machine.

**Foundations, 1978–1985.** 8086 (1978) was 16 bit, grown out of 8080 and compatible with it at source level. 80286 (1982) added protected mode, but once in it, only a reboot got you back to real mode. 80386 (1985) fixed the architecture's shape for decades: 32 bit, paged virtual memory, and virtual 8086 mode so old real-mode code could run inside the new protected world.

**Integration and parallelism, 1989–1995.** 486 (1989) pulled first-level cache and maths coprocessor onto the chip. Pentium (1993) went superscalar, with two integer pipelines able to retire two instructions per cycle. Pentium Pro (1995) made the deeper break: out-of-order execution, with x86 instructions translated into internal micro-operations. From then on x86 was an interface, no longer the real machine underneath.

**Frequency hits the wall, 2000–2006.** Pentium 4 (2000) chased clock speed with a very long pipeline and ran into the power wall. Meanwhile AMD extended the architecture to 64 bit in 2003 with AMD64, and Intel adopted the same instruction set. That was the first time the dominant extension did not come from Intel. From 2006, with Core 2, the direction shifted from frequency to core count.

**Wider vectors.** Across generations, vector extensions kept growing: MMX, SSE, AVX, AVX-512.

**Today.** Most of the complexity now sits in the layers below the instruction set: branch prediction, cache hierarchy, speculative execution. Spectre and Meltdown (2018) showed that speculative execution carried a security cost nobody had priced.
