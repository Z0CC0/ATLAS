Use Postgres. Switch to Redis only when volume really needs it.

**Why Postgres fits small project:**
- `SELECT ... FOR UPDATE SKIP LOCKED` handles up to roughly 1,000 jobs per minute. Small project rarely needs more.
- Job sits in same transaction as data. If write rolls back, job rolls back too. Job never starts for data that does not exist.
- Persistence comes free. If process dies, queue is still there.
- No new service. You already run Postgres.

**What Redis gives, and what it costs:**
- Much more volume and lower latency, under 1 ms.
- One more service to run, monitor and upgrade.
- You must configure persistence. Without AOF enabled, restart loses queued jobs.

Start with Postgres. Move to Redis when job volume outgrows it.
