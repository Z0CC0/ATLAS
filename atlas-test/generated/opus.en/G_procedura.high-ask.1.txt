Don't use `ALTER TABLE ALTER COLUMN TYPE` directly. It rewrites the whole table while holding an ACCESS EXCLUSIVE lock, so the service is down for as long as the rewrite runs. Do these steps in this order instead:

1. Check that every existing value can be converted. Count the rows whose value is not all digits. If the count isn't zero, fix those rows before going on.

2. Add the new column:
```sql
ALTER TABLE t ADD COLUMN colonna_int integer;
```

3. Fill it in batches of ten thousand rows, so the table is never locked for long.

4. Add a trigger that keeps `colonna` and `colonna_int` in step for the rest of the migration.

5. Change the code to read from `colonna_int`, and ship it.

6. Only after that, drop the old column:
```sql
ALTER TABLE t DROP COLUMN colonna;
```

Step 6 can't be undone. Once you drop the column, the only way to get its data back is to restore from a backup.
