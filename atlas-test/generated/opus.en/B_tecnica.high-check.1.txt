Connection pool exhaustion, not a slow query.

**Cause:** middleware at `db/session.py:47` releases the connection only on the success path. When the handler raises, `release()` is never reached, so the connection stays held until timeout. After a few hundred failed requests the pool is empty and every later request waits. That's why latency climbs instead of requests failing right away.

**Fix:** wrap the acquire in try/finally so the release also runs when the handler raises:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Raising `pool_size` looks like a fix but only hides the problem. The pool still empties, just later, and connections keep leaking. Raise it only after the fix is in, and only if your real load needs it.

To reproduce the behaviour before and after the change:

```
pytest tests/test_pool.py -k exhaustion -x
```
