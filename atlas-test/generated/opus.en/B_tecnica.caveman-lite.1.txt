Your API is running out of database connections. A slow query is not the cause. The connection pool runs dry because a code path leaks connections.

**The leak:** In the middleware at `db/session.py:47`, the connection is released only on the success path. When a handler raises an exception, `release()` never runs. That connection stays held until it times out.

**Why it slows down instead of failing:** Each failed request keeps one connection. After a few hundred failed requests, the pool is empty. Every request after that waits for a free connection. You see latency rise until the API locks up, not immediate errors.

**The fix:** Wrap the acquisition in `try/finally` so the release also runs on the error path:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

**Don't fix it by raising `pool_size`.** A bigger pool only hides the problem. It delays the moment the pool empties, but the connection leak is still there. Apply the fix first. After that, raise `pool_size` only if your real load needs more connections.

**To check it:** Run this before and after the change to reproduce the behaviour:

```
pytest tests/test_pool.py -k exhaustion -x
```
