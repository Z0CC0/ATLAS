Cache stores already-processed request prefix; later requests starting same way skip paying for it.

Prefix only: one different character at start, no reuse from that point on.

So stable parts first, changing parts after, never reverse.

Cache write costs more than normal read, so first request is more expensive.

Gain starts from second request, grows with number of turns.

**Pays off:** long conversations with large stable context, such as system instructions, attached documentation, tool definitions.

**Doesn't pay off:** single requests differing from each other. Write paid, never read back.

System line changing every turn, such as a clock, kills reuse of everything after it.
