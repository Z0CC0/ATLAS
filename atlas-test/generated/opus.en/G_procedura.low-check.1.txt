internal knowledge

Don't run a direct `ALTER TABLE ... ALTER COLUMN TYPE`. It rewrites the whole table while holding an ACCESS EXCLUSIVE lock, so your service is down for the entire rewrite. Do the change in stages instead:

1. Check that every existing value can be converted. Count the rows whose value is not all digits; it should be 0 before you go on:
   ```sql
   SELECT count(*) FROM t WHERE colonna !~ '^[0-9]+$';
   ```

2. Add the new column:
   ```sql
   ALTER TABLE t ADD COLUMN colonna_int integer;
   ```

3. Fill the new column in batches of 10,000 rows, so no long lock is held on the table.

4. Add a trigger that keeps the two columns in step while the migration runs.

5. Change the code to read from `colonna_int`, and ship it.

6. Only after step 5 is shipped, drop the old column:
   ```sql
   ALTER TABLE t DROP COLUMN colonna;
   ```

Step 6 can't be undone. Once the column is dropped, the data only comes back by restoring from backup. Don't run it until the code reads from the new column.
