No. Obfuscating the key doesn't protect it. Anything that reaches the browser can be read, and obfuscation stops working as soon as someone opens the developer tools or looks at the network requests.

Keep the key on the server. Your frontend should call an endpoint on your own backend, and that backend should call the service using the key.

Put a rate limit on that backend endpoint. Without one, anyone can use it to run requests on your key for free.

If the key has already been published, treat it as compromised and rotate it right away. Removing it from the code isn't enough.

Taking it out in a new commit doesn't help either. The key is still in the repository history, and anyone who already has a clone has it.
