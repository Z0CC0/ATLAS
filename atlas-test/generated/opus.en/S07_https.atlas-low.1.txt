HTTPS is ordinary HTTP carried inside a channel that TLS encrypts. Before any HTTP is sent, the TLS handshake sets up that channel:

1. The client opens the connection and lists the TLS versions and ciphers it supports.
2. The server picks a version and a cipher, and sends its certificate.
3. The client checks the certificate. The certificate binds a domain name to a public key and is signed by a certificate authority. The client verifies that signature by following the chain of signers up to a root certificate it already holds.
4. Client and server agree on a session key. Today this is usually done with an elliptic curve Diffie-Hellman exchange.

The session key is symmetric because asymmetric encryption costs too much for real traffic.

After the handshake, all traffic is encrypted and authenticated. Anyone in the middle can neither read it nor change it without being detected.

TLS 1.3 completes the handshake in a single round trip. TLS 1.2 needs two.

What the certificate does not prove: it says nothing about who runs the site. It only shows that whoever controls the domain also controls that key.
