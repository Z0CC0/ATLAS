HTTPS is HTTP running inside a channel that TLS encrypts.

**Handshake:**

1. Client opens the connection. Client lists the TLS versions and ciphers it supports.
2. Server picks one cipher and one version. Server sends its certificate.
3. Certificate binds a domain name to a public key. A certificate authority signs it.
4. Client verifies the signature by walking the chain up to a root certificate it already holds.
5. Client and server agree on a session key. Today this is typically an elliptic curve Diffie-Hellman exchange.

**Why a symmetric session key:** asymmetric encryption costs too much for real traffic. Asymmetric crypto only sets up the session. A symmetric key carries the data.

**After the handshake:** traffic is encrypted and authenticated. Anyone in the middle can't read it or modify it.

**Speed:** TLS 1.3 needs one round trip for the handshake. TLS 1.2 needs two.

**Limit:** the certificate says nothing about who runs the site. It only proves that the domain controls that key.
