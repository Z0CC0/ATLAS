HTTPS is HTTP inside a channel that TLS encrypts. TLS sets up that channel with a handshake:

1. **Client hello.** Client opens the connection and lists the TLS versions and ciphers it supports.
2. **Server hello.** Server picks one version and one cipher. It also sends its certificate.
3. **Certificate check.** The certificate binds a domain name to a public key, and a certificate authority signs it. Client checks the signature by walking the chain up to a root it already holds.
4. **Key agreement.** Client and server agree on a session key. Today this is usually an elliptic curve Diffie-Hellman exchange.
5. **Encrypted traffic.** From here on, all traffic is encrypted and authenticated. Anyone in the middle can't read it or change it.

**Why the session key is symmetric:** asymmetric encryption costs too much for real traffic. The asymmetric part only sets up the connection. The symmetric key then carries the data.

**Speed:** TLS 1.3 finishes the handshake in one round trip. TLS 1.2 needs two.

**What the certificate doesn't prove:** it says nothing about who runs the site. It only says that the domain controls that key.
