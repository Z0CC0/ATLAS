Usually no. On a column with only three distinct values, the planner usually won't use a B-tree index.

Each value tends to match a large share of the table. Once a filter selects more than roughly 5-10 per cent of the rows, the planner prefers a sequential scan.

The index still costs extra work on every write and takes up disk space, so you pay for it without getting anything back.

The exception is when one of the values is rare. A partial index on that value does get used, for example:

```sql
CREATE INDEX ON orders (status) WHERE status = 'failed';
```
