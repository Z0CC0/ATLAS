Connection pool exhaustion, not slow query.

Middleware at `db/session.py:47` releases connection only on success path. Handler raises exception, `release()` never reached, connection held until timeout. After few hundred failed requests, pool empties; every later request waits. Hence rising latency instead of immediate errors.

**Fix:** wrap acquisition in try/finally so release also runs on error path:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Don't just raise `pool_size`. Looks like fix but only masks leak: delays moment pool empties, leak stays. Raise `pool_size` only after fix is in, and only if real load calls for it.

Reproduce before and after change:

```
pytest tests/test_pool.py -k exhaustion -x
```
