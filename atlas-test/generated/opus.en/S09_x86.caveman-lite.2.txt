# How x86 evolved, from the 8086 to today

x86 started as a 16-bit chip. Over time it became a stable instruction set that sits on top of very different machines. The story has three phases.

## 1. Building the architecture (1978–1989)

- **8086 (1978).** A 16-bit processor that grows out of the 8080. It keeps source-level compatibility with the 8080, so existing code carries over. That choice set the pattern: every later chip keeps the past working.
- **80286 (1982).** Introduces protected mode. The design has one flaw: once the chip enters protected mode, it cannot return to real mode without a reboot.
- **80386 (1985).** This is the chip that makes x86 a modern architecture. It brings 32 bit, paged virtual memory and virtual 8086 mode. Virtual 8086 mode fixes the 286 problem, because old real-mode code can now run inside the protected environment.
- **486 (1989).** Puts the first-level cache and the maths coprocessor on the chip. Parts that used to sit outside the processor now sit inside it.

## 2. The instruction set becomes an interface (1993–2000)

- **Pentium (1993).** Superscalar. It has two integer pipelines, so it can retire two instructions per cycle.
- **Pentium Pro (1995).** The turning point. It adds out-of-order execution and translates x86 instructions into internal micro-operations.

After the Pentium Pro, x86 is an interface and no longer the real machine underneath. The instructions you write describe what you want done. The hardware decides how it actually gets done.

- **Pentium 4 (2000).** Chases clock frequency with a very long pipeline and hits the power wall. Raising frequency further is no longer practical.

## 3. New directions (2003–today)

- **AMD64 (2003).** AMD extends the architecture to 64 bit, and Intel adopts the same instruction set. This is the first time the dominant x86 extension does not come from Intel.
- **Core 2 (2006).** After the Pentium 4, the focus moves from frequency to core count. Performance now comes from more cores instead of a faster single core.
- **Vector extensions.** These grow generation by generation: MMX, then SSE, then AVX, then AVX-512.

Today most of the complexity sits in the layers below the instruction set: branch prediction, the cache hierarchy and speculative execution. In 2018, Spectre and Meltdown showed that speculative execution had a security cost that nobody had priced in. That speculation is part of the hidden machinery that has sat under the x86 interface since the Pentium Pro.

## The thread through all of it

x86 kept compatibility with its past at every step. What changed was the machine underneath. The gains came first from wider words and on-chip integration, then from parallel pipelines, then from out-of-order execution, and then from more cores and wider vectors. Each of those layers added performance, and in the case of speculative execution it also added risk.
