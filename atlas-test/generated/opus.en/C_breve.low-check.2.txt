Usually no. On a column with only three distinct values, the planner normally won't use a B-tree index.

When a filter selects more than roughly 5–10 per cent of rows, the planner prefers a sequential scan. With three values, each value usually matches far more rows than that.

The index still costs extra work on every write and takes disk space, so you pay for it without getting faster reads.

The exception is when one value is rare. A partial index on just that value does work, for example:

```sql
CREATE INDEX ON orders (status) WHERE status = 'failed';
```
