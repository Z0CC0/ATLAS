Cache stores already-processed prefix of request; later requests starting same way don't pay for it again.

Prefix only: one different character at start, no reuse from that point on.

So stable parts first, changing parts after, never reverse.

Writing to cache costs more than normal read, so first request costs more.

Gain starts from second request onward, grows with number of turns.

Pays off: long conversations with large stable context, such as system instructions, attached documentation, tool definitions.

Doesn't pay off: single requests that differ from each other. You pay the write, never read it back.

Trap: system line changing every turn, such as a clock, kills reuse of everything after it.
