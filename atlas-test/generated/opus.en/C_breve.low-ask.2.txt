**No**, usually not. On low cardinality column, planner normally doesn't use B-tree index.

Planner prefers sequential scan once filter selects more than roughly 5-10 per cent of rows. With only three values, most filters select more than that. Index still costs writes and disk space, so you pay for it and get nothing back.

Exception: one value rare and you filter on it. Partial index on that rare value does work:

```sql
CREATE INDEX orders_failed_idx ON orders (id) WHERE status = 'failed';
```
