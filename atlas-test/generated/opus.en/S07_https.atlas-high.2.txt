HTTPS is ordinary HTTP carried inside a channel that TLS encrypts.

Connection setup, in order:

1. The client opens the connection and lists the TLS versions and ciphers it supports.
2. The server picks a version and a cipher, and sends its certificate.
3. The certificate binds a domain name to a public key, and a certificate authority signs it. The client checks that signature by following the chain up to a root certificate it already holds.
4. Client and server agree on a session key, usually today through an elliptic curve Diffie-Hellman exchange. The key is symmetric because asymmetric encryption costs too much for real traffic.
5. From then on, traffic is encrypted and authenticated. Anyone in the middle can neither read it nor change it.

TLS 1.3 completes this handshake in one round trip. TLS 1.2 needs two.

The certificate does not say who runs the site. It only proves that whoever controls the domain also controls that key.
