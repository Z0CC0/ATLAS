HTTPS is HTTP running inside a channel encrypted by TLS. Before any page data moves, client and server run a TLS handshake:

1. Client opens the connection and lists the TLS versions and ciphers it supports.

2. Server picks a cipher and a version, then sends its certificate.

3. Client checks the certificate. It binds a domain name to a public key and is signed by a certificate authority. The client verifies that signature by walking the chain up to a root certificate it already holds.

4. Client and server agree on a session key, today usually through an elliptic curve Diffie-Hellman exchange.

The session key is symmetric because asymmetric encryption costs too much for real traffic. Asymmetric cryptography is used only to set up the connection.

From then on, traffic is encrypted and authenticated. Nobody in the middle can read it or change it without being detected.

The handshake costs time. TLS 1.3 needs a single round trip, while TLS 1.2 needs two.

**The padlock doesn't tell you who runs the site.** A certificate proves only that whoever controls that domain also holds that key. A phishing site on its own domain can have a perfectly valid certificate.
