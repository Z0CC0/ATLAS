HTTPS is HTTP running inside a channel that TLS encrypts. Before any page data moves, client and server run a handshake:

1. Client opens the connection and says which TLS versions and ciphers it supports.
2. Server picks a version and a cipher, and sends its certificate.
3. Client checks the certificate. It binds a domain name to a public key and carries a certificate authority's signature. Client verifies that signature by following the chain up to a root certificate it already holds.
4. Client and server agree on a session key. Today this is usually done with an elliptic curve Diffie-Hellman exchange.

From then on, all traffic is encrypted and authenticated. Anyone in the middle can't read it or change it.

The session key is symmetric because asymmetric encryption costs too much to use on real traffic. Public keys are only used to set up the connection.

TLS 1.3 needs one round trip for the handshake. TLS 1.2 needs two, so connections open faster on 1.3.

A certificate doesn't tell you who runs the site. It only proves that whoever controls that domain holds that key.
