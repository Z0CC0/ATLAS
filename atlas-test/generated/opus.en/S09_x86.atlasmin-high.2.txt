Over about forty years, x86 went from a 16-bit chip to an instruction set that sits in front of a far more complex machine. The story actually starts slightly before the eighties.

**8086, 1978**: 16 bit, grew out of the 8080 and stayed compatible with it at source level.

80286, 1982: introduced protected mode, but there was no way back to real mode without a reboot.

80386, 1985: brought 32 bit, paged virtual memory and virtual 8086 mode.

486, 1989: moved the first-level cache and the maths coprocessor onto the chip.

Pentium, 1993: superscalar, with two integer pipelines that could retire two instructions per cycle.

**Pentium Pro, 1995**: introduced out-of-order execution and translated x86 instructions into internal micro-operations. From then on, x86 was an interface rather than the real machine underneath.

Pentium 4, 2000: chased frequency with a very long pipeline and hit the power wall.

AMD64, 2003: AMD extended the architecture to 64 bit, and Intel adopted the same instruction set. It was the first time the dominant extension did not come from Intel.

Core 2, 2006: the focus shifted from frequency to core count.

Across these generations, the vector extensions kept growing: MMX, SSE, AVX, AVX-512.

Today the complexity sits in the layers below the instruction set: branch prediction, the cache hierarchy and speculative execution.

Spectre and Meltdown, 2018: showed that speculative execution carried a security cost nobody had priced.
