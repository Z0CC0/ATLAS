internal knowledge

Prompt caching saves the part of a request that's already been processed so later requests starting the same way don't pay for it again. It pays off on long conversations where a large part of the context stays the same.

**How it works.** Cache keeps only the prefix. Change one character near the start and nothing from that point on gets reused. So stable parts go first and changing parts after, never the other way round.

**Cost.** Writing to cache costs more than a normal read, so the first request costs more. Savings start from the second request and grow with each turn.

When it pays off: long conversations with a large stable context, such as system instructions, attached documentation and tool definitions.

When it doesn't: single requests that differ from each other. You pay for the write and never read it back.

One common trap: a system line that changes every turn, like a clock, stops reuse of everything after it. Put that kind of line at the end, or remove it.
