HTTPS is plain HTTP carried inside a channel encrypted by TLS. Setting up that channel is called the handshake:

1. Client opens connection and lists TLS versions and ciphers it supports.

2. Server picks one cipher and one version, and sends its certificate.

3. Client verifies certificate signature by walking chain up to root it already holds.

4. Both sides agree on session key, today typically through elliptic curve Diffie-Hellman exchange.

Certificate binds domain name to public key and carries signature of certificate authority. It says nothing about who runs site, only that domain controls that key.

Session key symmetric, because asymmetric encryption costs too much for real traffic.

After handshake, traffic encrypted and authenticated, so anyone in the middle can neither read nor modify it.

TLS 1.3 cuts handshake to single round trip. TLS 1.2 needs two.
