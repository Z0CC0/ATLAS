internal knowledge

Avoid a direct `ALTER TABLE ... ALTER COLUMN ... TYPE`. It rewrites the whole table while holding an ACCESS EXCLUSIVE lock, so the service is down for the entire rewrite. Do it in steps instead, in this order:

1. Check that every value converts: count the rows where `colonna` is not all digits. Fix those rows before going on.

2. Add the new column:
```sql
ALTER TABLE t ADD COLUMN colonna_int integer;
```

3. Fill `colonna_int` in batches of 10,000 rows, so no long lock is held on the table.

4. Add a trigger that keeps `colonna` and `colonna_int` in step while the migration runs.

5. Change the code to read from `colonna_int`, and ship it.

6. Only after step 5 is live, drop the old column:
```sql
ALTER TABLE t DROP COLUMN colonna;
```

Step 6 cannot be undone. Once the column is dropped, its data only comes back by restoring from backup. Do not run it until the code is reading from the new column.
