internal knowledge

Don't run a direct `ALTER TABLE ... ALTER COLUMN TYPE`. It rewrites the whole table under an ACCESS EXCLUSIVE lock, so the service is down for the entire rewrite. Do it in six steps instead, in this order:

1. Check that every existing value converts: count the rows where the value is not all digits.

2. Add the new column:
```sql
ALTER TABLE t ADD COLUMN colonna_int integer;
```

3. Fill it in batches of 10,000 rows so no long lock is held on the table.

4. Add a trigger that keeps the two columns in step during the migration.

5. Change the code to read from `colonna_int` and ship it.

6. Only after step 5 is shipped, drop the old column:
```sql
ALTER TABLE t DROP COLUMN colonna;
```

Step 6 can't be undone. Once the column is dropped, the data comes back only through a restore from backup.
