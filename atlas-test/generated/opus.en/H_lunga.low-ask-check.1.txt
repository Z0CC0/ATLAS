internal knowledge

Prompt caching stores the already-processed beginning of a request, so later requests that start the same way don't pay to process it again.

Matching works only on the **prefix**. If one character differs near the start, nothing from that point on gets reused. Put stable parts first and parts that change after them, never the other way round. A system line that changes every turn, such as a clock, breaks reuse for everything after it.

Writing to the cache costs more than a normal read, so the first request costs more. Savings start with the second request and grow with every turn that reuses the prefix.

**When it pays off:** long conversations built on a large stable context, such as system instructions, attached documentation and tool definitions.

When it doesn't: single requests that differ from each other. You pay for the cache write and never read it back.
