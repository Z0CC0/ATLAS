HTTPS = plain HTTP running inside channel encrypted by TLS. HTTP itself unchanged. TLS wraps it.

**Handshake**

1. Client opens connection. Client lists TLS versions and ciphers it supports.
2. Server picks one cipher and one version. Server sends back its certificate.
3. Certificate binds domain name to public key. Certificate authority (CA) signs it.
4. Client checks signature. Client walks chain upward, cert by cert, until it reaches root it already holds. Chain ends at trusted root, so cert is accepted.
5. Client and server agree on session key. Today usually done with elliptic curve Diffie-Hellman (ECDHE) exchange.

**Why symmetric session key**

Asymmetric encryption costs too much for real traffic volume. Public/private keys only help set things up. Bulk data uses fast symmetric key.

**After handshake**

All traffic is encrypted and authenticated. Anyone in middle cannot read it. Anyone in middle cannot modify it without detection.

**TLS 1.2 vs 1.3**

TLS 1.2 handshake needs two round trips. TLS 1.3 cuts it to one round trip, so connection setup is faster.

**What padlock does not mean**

Certificate says nothing about who runs site. Certificate only proves that domain controls that key. Phishing site with valid cert still gets padlock.
