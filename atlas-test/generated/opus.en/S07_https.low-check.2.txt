internal knowledge

HTTPS is ordinary HTTP carried inside a channel that TLS encrypts. Before any HTTP is sent, client and server run a handshake:

1. Client opens the connection and says which TLS versions and ciphers it supports.

2. Server picks a version and a cipher, and sends its certificate.

3. Client checks the certificate. The certificate binds a domain name to a public key, and a certificate authority signs it. The client verifies that signature by following the chain up to a root certificate it already holds.

4. Client and server agree on a session key. Today this is usually done with an elliptic curve Diffie-Hellman exchange.

The session key is symmetric because asymmetric encryption costs too much for real traffic. After the handshake, all traffic is encrypted and authenticated, so anyone in the middle can neither read it nor change it.

TLS 1.3 makes the handshake shorter: it takes a single round trip, where TLS 1.2 needed two.

**The certificate tells you nothing about who runs the site.** It only proves that whoever controls the domain also controls that key.
