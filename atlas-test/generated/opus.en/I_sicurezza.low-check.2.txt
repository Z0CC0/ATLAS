No. Anything that reaches the browser can be read, and obfuscation stops working as soon as someone opens the developer tools or watches the network requests.

Keep the key on the server. Your frontend should call an endpoint on your own backend, and that backend calls the service with the key.

Put a rate limit on that backend endpoint. Without one, anyone can use your endpoint to spend your key for free.

If the key has already been published anywhere, treat it as compromised and rotate it right away. Removing it from the code isn't enough.

Removing it in a new commit isn't enough either. The key is still in the repository history, and anyone who has already cloned the repository has it.
