Usually no. On a column with only three distinct values, a plain B-tree index normally goes unused. The planner picks a sequential scan whenever the filter matches more than about 5-10 per cent of the rows, and with three values most filters match far more than that. Every write still has to update the index, and it still takes up disk space.

The exception is when one of the values is rare. A partial index on that value does get used:

```sql
CREATE INDEX ON orders (status) WHERE status = 'failed';
```
