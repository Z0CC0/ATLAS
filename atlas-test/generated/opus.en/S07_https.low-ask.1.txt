HTTPS: plain HTTP carried inside channel that TLS encrypts. Before any page data moves, client and server run handshake to set that channel up:

1. Client opens connection, lists TLS versions and ciphers it supports.

2. Server picks one version and one cipher, sends back its certificate.

3. Client checks certificate. Certificate binds domain name to public key, signed by certificate authority. Client verifies signature by walking chain of signers up to root certificate it already holds.

4. Client and server agree session key, today typically through elliptic curve Diffie-Hellman exchange.

From then on, all traffic encrypted and authenticated. Anyone in the middle can neither read it nor modify it.

Session key symmetric because asymmetric encryption costs too much for real traffic. Asymmetric cryptography only helps set the connection up. Symmetric key then carries the actual data.

TLS 1.3 completes handshake in single round trip. TLS 1.2 needed two.

One common misreading: certificate says **nothing about who runs site**. It proves only that whoever controls that domain also controls that key.
