HTTPS is ordinary HTTP carried inside a channel encrypted by TLS. Before any HTTP goes over the connection, the client and server run a TLS handshake:

1. The client opens the connection and says which TLS versions and ciphers it supports.

2. The server picks a cipher and a version, and sends its certificate.

3. The certificate binds a domain name to a public key and is signed by a certificate authority. The client checks that signature by walking the chain up to a root certificate it already holds.

4. The client and server agree on a session key. Today this is usually done with an elliptic curve Diffie-Hellman exchange.

The session key is symmetric because asymmetric encryption costs too much to use on real traffic.

From then on, all traffic is encrypted and authenticated. Anyone in the middle can neither read it nor modify it.

TLS 1.3 completes the handshake in a single round trip. TLS 1.2 needs two.

One limit is often misunderstood. The certificate says nothing about who runs the site. It only says that whoever controls that domain controls that key.
