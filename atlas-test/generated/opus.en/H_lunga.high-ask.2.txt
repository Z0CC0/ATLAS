Cache keeps already-processed prefix of request; later requests starting same way skip paying for it again.

Works only on prefix. One different character at start: no reuse from that point on.

So stable parts first, changing parts after, never reverse.

Cache write costs more than normal read, so first request more expensive.

Gain starts from second request, grows with number of turns.

**Pays off:** long conversations with large stable context, such as system instructions, attached documentation, tool definitions.

**Doesn't pay off:** single requests differing from each other. You pay the write and never read it back.

Watch out: a system line that changes every turn, such as a clock, kills reuse of everything after it.
