internal knowledge

Don't run `ALTER TABLE ... ALTER COLUMN TYPE` directly. On ten million rows it rewrites the whole table while holding an ACCESS EXCLUSIVE lock, so the service is down for the whole rewrite. Use a new column and switch over in six steps, in this order:

1. Check that every existing value can be converted. Count the rows whose value is not all digits. If the count isn't zero, fix those rows before going further.

2. Add the new column:
   ```sql
   ALTER TABLE t ADD COLUMN colonna_int integer;
   ```

3. Fill `colonna_int` in batches of ten thousand rows, so no long lock is held on the table.

4. Add a trigger that keeps `colonna` and `colonna_int` in step while the migration runs, so writes that happen during the backfill aren't lost.

5. Change the code to read from `colonna_int`, and ship it.

6. Only after the code is live and reading from the new column, drop the old one:
   ```sql
   ALTER TABLE t DROP COLUMN colonna;
   ```

**Step 6 can't be undone.** Once `colonna` is dropped, its data comes back only by restoring from a backup. Until then, the old column is your way back if anything goes wrong.
