Cause is **connection pool exhaustion**, not slow query.

**What happens**
- Middleware at `db/session.py:47` releases connection only on success path.
- When handler raises exception, `release()` is never reached. Connection stays held until timeout.
- After few hundred failed requests, pool is empty. Every later request waits for free connection.
- So you see rising latency, not immediate errors, then lockup.

**Fix**
Wrap acquisition in `try/finally`. Release then runs on error path too:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

**Do not raise `pool_size` as fix.** Bigger pool only masks leak. Pool still empties, just later. Raise `pool_size` only after fix is in, and only if real load needs it.

**Verify**
Run test before and after change to reproduce behaviour:

```
pytest tests/test_pool.py -k exhaustion -x
```
