No. Anything that reaches the browser can be read, and obfuscation stops working as soon as someone opens the developer tools or looks at the network requests.

Keep the key on the server instead. Your frontend calls an endpoint on your own backend, and that endpoint calls the service with the key.

Put a rate limit on that endpoint. Without one, anyone can use it to spend your key for free.

If the key has already been published, treat it as compromised and rotate it right away. Removing it from the code doesn't fix that.

Taking it out in a new commit isn't enough either. The key stays in the repository history, and anyone who already has a clone has it.
