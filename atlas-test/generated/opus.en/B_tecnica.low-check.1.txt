Cause: connection pool exhaustion, not slow query.

Middleware at `db/session.py:47` releases connection only on success path. When handler raises exception, `release()` never reached, so connection stays held until timeout. After few hundred failed requests, pool empties and every later request waits for free connection. That's why latency climbs instead of requests failing immediately.

Fix: wrap acquisition in try/finally so release also happens on error path:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Raising `pool_size` looks like fix but only masks leak: pool still empties, just later. Apply the try/finally fix first. Raise `pool_size` only after that, and only if real load calls for it.

To reproduce behaviour before and after change:

```
pytest tests/test_pool.py -k exhaustion -x
```
