Connection pool exhaustion, not slow query. Your middleware leaks a connection on every failed request.

At `db/session.py:47` middleware releases connection only on success path. When handler raises exception, `release()` never reached, so connection stays held until timeout. After a few hundred failed requests pool empties and every later request waits for a free connection. That's why you see rising latency instead of immediate errors.

Fix: wrap acquisition in try/finally so release happens on error path too.

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Don't raise `pool_size` as the fix. Looks like one but only masks leak: it pushes back the moment pool empties without removing the leak. Raise it only after fix is in, and only if real load calls for it.
