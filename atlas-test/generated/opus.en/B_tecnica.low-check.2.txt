Connection pool exhaustion, not slow query. Middleware at `db/session.py:47` releases connection only on success path. When handler raises exception, `release()` never reached, so connection stays held until timeout. After few hundred failed requests pool empties and every later request waits for free connection. That's why you see rising latency instead of immediate errors.

Fix: wrap acquisition in try/finally so release happens on error path too.

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Don't reach for higher `pool_size` first. Looks like fix but only masks leak: pushes back moment pool empties, leak still there. Raise it only after fix is in, and only if real load calls for it.
