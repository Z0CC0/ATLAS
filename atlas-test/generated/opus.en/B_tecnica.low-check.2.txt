Connection pool exhaustion, not slow query. Middleware at `db/session.py:47` releases connection only on success path.

When handler raises exception, `release()` never reached, so connection stays held until timeout. After few hundred failed requests, pool empties and every later request waits for free connection. That's why latency rises instead of immediate errors.

Fix: wrap acquisition in try/finally so release also happens on error path:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Don't raise `pool_size` as fix. It only masks the problem: pool empties later, but connections still leak. Apply the try/finally fix first. After that, raise `pool_size` only if real load needs it.

To reproduce the behaviour, run this before and after the change:

```
pytest tests/test_pool.py -k exhaustion -x
```
