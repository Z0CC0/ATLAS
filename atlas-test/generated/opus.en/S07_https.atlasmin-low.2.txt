HTTPS is ordinary HTTP sent inside a channel that TLS encrypts. Before any HTTP is exchanged, client and server run a handshake to set up that channel:

1. The client opens the connection and says which TLS versions and ciphers it supports.

2. The server picks a version and a cipher, and sends its certificate.

3. The client checks the certificate. A certificate binds a domain name to a public key and is signed by a certificate authority. The client verifies that signature by following the chain of signers up to a root certificate it already holds.

4. Client and server agree on a session key. Today this is usually done with an elliptic curve Diffie-Hellman exchange.

The session key is symmetric because asymmetric encryption costs too much to use on real traffic. From then on, all traffic is encrypted and authenticated. Anyone in the middle can neither read it nor change it.

The handshake has a cost in round trips. TLS 1.2 needs two, and TLS 1.3 cuts it to one.

The certificate does **not** tell you who runs the site. It only proves that whoever controls the domain also controls that key.
