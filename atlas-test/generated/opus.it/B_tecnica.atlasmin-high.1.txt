La tua API esaurisce il connection pool. Il problema non è una query lenta.

In `db/session.py:47` il middleware rilascia la connessione solo quando la richiesta va a buon fine. Se l'handler solleva un'eccezione, `release()` non viene mai raggiunto e la connessione resta occupata fino al timeout. Dopo qualche centinaio di richieste fallite il pool si svuota e ogni richiesta successiva resta in attesa. Per questo vedi latenze crescenti invece di errori immediati.

Per correggerlo, avvolgi l'acquisizione in un try/finally, così la connessione viene rilasciata anche quando c'è un errore:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Per ora non aumentare `pool_size`. Sembra risolvere, ma maschera soltanto il problema: il pool si esaurisce più tardi e le connessioni continuano a essere perse. Aumentalo solo dopo aver applicato la correzione, se il carico reale lo richiede.

Per riprodurre il comportamento prima e dopo la modifica:

```
pytest tests/test_pool.py -k exhaustion -x
```
