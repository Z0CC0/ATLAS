La tua API esaurisce il connection pool: non dipende da una query lenta.

In `db/session.py:47` il middleware rilascia la connessione solo nel percorso di successo. Quando l'handler solleva un'eccezione, `release()` non viene mai raggiunto e la connessione resta occupata fino al timeout. Dopo qualche centinaio di richieste fallite il pool è vuoto e ogni richiesta successiva resta in attesa. Per questo vedi latenze crescenti invece di errori immediati.

Correzione: avvolgi l'acquisizione in un `try/finally`, così la connessione viene rilasciata anche quando c'è un errore:

```python
conn = pool.acquire()
try:
    return handler(conn, request)
finally:
    pool.release(conn)
```

Non aumentare `pool_size` per risolvere: sembra funzionare, ma nasconde soltanto il problema. Il pool si esaurisce più tardi e le connessioni continuano a perdersi. Aumentalo solo dopo aver applicato la correzione, e solo se il carico reale lo richiede.

Per riprodurre il comportamento prima e dopo la modifica:

```
pytest tests/test_pool.py -k exhaustion -x
```
