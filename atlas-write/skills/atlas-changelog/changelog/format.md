# The entry and the version

## The format is the file's

A `CHANGELOG.md` that exists sets the format: its headings, its date style, its order (newest
first), its link style. Match it exactly, including its mistakes of style; a changelog with two
styles is worse than one with a poor style. None exists: Keep a Changelog, because tools and
readers know it:

```
## [1.4.0] - 2026-10-15
### Added
- …
### Changed
- …
### Fixed
- …
### Removed
- …
```

An `[Unreleased]` section at the top collects lines between releases when the project uses
one; a release moves it under a version heading with the date.

## A line

Starts with what the reader notices, in the present tense of the result ("exports now
include the clip"), not the commit's imperative. Says where when the project has parts
("recorder:", "CLI:"). Ends with the reference the project uses (`#123`, a commit short hash)
when the project's lines have one. One sentence; a second only for what the reader must do.
No "various fixes", no "improvements", no "minor".

## The version

Decided from the lines, after they are written, by what the reader has to do:
- a line marked breaking → the first number (or, before 1.0, the second, when the project
  follows that convention; check its history);
- something added or a default changed with nothing broken → the second;
- only fixes → the third.
The project's own scheme wins over this: a project that only ever moves the last number, or
that uses dates, or whose version is a build count, keeps its scheme, and the entry says what
the scheme is when a reader could be surprised.

## The manifest

The version lives in one or more files (`package.json`, `pyproject.toml`, `Cargo.toml`, a
plugin manifest, a `VERSION` file, the app's about box); find every copy with a search for
the current version string before changing one, and change all of them in the same step, or
none. A lock file is regenerated by the tool, not edited.

## What the entry is not

Not the commit list. Not a place for apologies or thanks. Not a plan: nothing that is not in
the range is in the entry, and "coming soon" belongs to a roadmap file.
